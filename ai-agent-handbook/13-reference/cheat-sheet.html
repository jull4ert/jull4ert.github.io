日常流程（一頁版）

1 需求模糊 → 計畫模式 → 讓 agent 訪談你（一次一題、附建議答案） 2 寫規格（可驗收條件）→ 需求審查（找缺漏） 3 拆成小任務 → 存成計畫檔 4 每個任務：新對話 → 先寫失敗的測試 → 實作 → 看 diff 5 驗證：建置、測試、實際操作 → 證據表 6 交叉審查 → 你裁決 7 commit、PR（誠實說明驗證與 AI 輔助）→ 回寫 CLAUDE.md

啟動與非互動（已實測）

指令用途
claude在目前資料夾啟動互動對話
claude -p "提示"非互動，輸出後結束
--output-format text|json|stream-json搭配 -p 的輸出格式
-c / --continue、-r / --resume接續最近／指定的對話
--permission-mode可選：plan、acceptEdits、auto、manual、dontAsk、bypassPermissions
--allowedTools / --disallowedTools限定允許或拒絕的工具，例如 "Bash(git *)"
--max-turns N限制回合數（實測可用；本機版本的 --help 未列出）
--max-budget-usd 金額用量金額上限，只搭配 -p
-w / --worktree [名稱]在新的 git worktree 中工作
--model、--effort low|medium|high|xhigh|max選模型、思考強度
--add-dir額外開放存取的資料夾
--agents以 JSON 定義自訂 agent
--bare精簡模式：略過 hooks、外掛同步、CLAUDE.md 自動探索等
claude doctor檢查安裝健康狀態

MCP 與外掛（已實測 --help）

指令說明
claude mcp add --transport http 名稱 網址加入遠端 MCP
claude mcp add 名稱 -e KEY=值 -- npx 套件加入本機（stdio）MCP
-s / --scope local|user|project設定範圍（預設 local）
claude mcp list / get 名稱列出、檢視
claude plugin marketplace add 來源加入外掛來源（網址、路徑或 GitHub 倉庫）
claude plugin install 外掛@來源安裝外掛
claude plugin details 名稱檢視元件清單與預估 token 成本

什麼時候 /clear

  • 任務完成、要做新任務。
  • agent 走錯方向、再補修正只會越補越亂。
  • 對話很長，開始忘記先前的約定。
  • 換階段（訪談 → 規格 → 實作）。

省 Token 速記

  • 一個對話一件事；完成就 /clear。
  • 先計畫模式，避免整包重做。
  • 指令具體、限定檔案與範圍、限制輸出格式。
  • CLAUDE.md 精簡；停用用不到的 MCP 與 skill（可用 claude plugin details 看成本）。
  • 探索與審查交給 subagent，限制回報長度。
  • 只跑相關測試；工具輸出只留失敗與摘要。
