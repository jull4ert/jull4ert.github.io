CLAUDE.md：專案常駐規範

每次對話都會讀，所以要短、準、可執行。

放在哪裡

位置範圍
專案根目錄 CLAUDE.md整個專案，建議納入版本控制，團隊共用
子資料夾 CLAUDE.mdagent 處理該資料夾檔案時才載入，適合模組專屬規則
~/.claude/CLAUDE.md你個人的跨專案偏好（語言、風格）
CLAUDE.local.md僅自己、不入版控的專案設定

該寫什麼

  • 指令：建置、測試、啟動、格式化怎麼下（agent 無法猜）。
  • 架構地圖：重要資料夾各管什麼，一兩行即可。
  • 非顯而易見的慣例：與一般做法不同、讀程式看不出來的規則。
  • 禁忌：不要動的檔案、不要用的做法，附一句原因。
  • 完成標準：「改完要跑哪些檢查」。

不該寫什麼

  • 讀程式就看得出來的事、一般語言常識。
  • 大段說明文件（改成連結或 @檔案 引用）。
  • 一次性的任務指示（那是對話，不是規範）。
  • 會很快過時的細節（版本號、暫時性狀態）。

範例（精簡版）

# 專案：OrderService
## 指令
- 建置：dotnet build
- 測試：dotnet test --filter Category!=Slow
- 格式化：dotnet format
## 架構
- src/Domain 領域模型；src/Application 用例；src/Web API 層
## 慣例
- 查詢走 Query 物件，不在 Controller 直接寫 LINQ（原因：統一分頁與權限）
- 新增 API 必須有對應整合測試
## 禁忌
- 不要修改 Migrations/ 內既有檔案
## 完成標準
- dotnet test 全綠；變更說明列出影響的 API
官方最佳實踐頁也提到：路徑專屬的規則可放在 .claude/rules/ 並用 paths: 限定，只在處理相關檔案時載入；個人偏好放 CLAUDE.local.md 並加入 gitignore。細節以官方文件為準。

維護原則

  • 控制長度：官方記憶指南建議 200 行以內，越短越好；越長遵守度越低。
  • 用 @路徑 匯入細節文件，保持主檔精簡。
  • 從錯誤長出規則：agent 犯同樣的錯第二次，才寫進去。
  • 定期瘦身：刪掉已經不犯的、過時的。
  • 寫成肯定、具體、可驗證：「用 X」優於「不要用 Y」，「函式不超過 40 行」優於「保持簡潔」。

省 Token 技巧

CLAUDE.md 每次對話都載入，等於每一輪都在付費。它是 Token 成本最容易被忽略的地方。

  • 控制長度：每多一行都是每次對話的固定成本；只留 agent 無法從程式碼得知的資訊。
  • 用子資料夾 CLAUDE.md：模組專屬規則放在該資料夾，只在處理該區檔案時載入。
  • 匯入要節制：@檔案 匯入的內容也會跟著載入，別把大型文件整份匯入；改成「需要時請讀 docs/xxx.md」的索引文字。
  • 刪除已不犯的規則：定期瘦身，過時規則白白佔位。
  • 量測：用 /context 看 memory 佔多少。
