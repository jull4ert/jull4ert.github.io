Subagent：獨立情境的專職助手

隔離大量輸出、平行作業、讓審查者有獨立性。

它是什麼

Subagent 是被主 agent 派出去的助手：有自己的情境視窗、自己的系統提示、自己限定的工具。它做完事只把結論回報給主對話，過程不佔主對話情境。

好處說明
隔離翻遍幾十個檔案的探索，只回傳一段摘要
獨立看不到作者的對話歷史，適合審查（見 05）
專職固定角色、固定輸出格式、限定工具
平行多個 subagent 可同時進行
成本彈性可指定較小的模型處理簡單工作

內建與自訂

  • 系統通常內建幾種通用 subagent（例如專做唯讀探索、專做規劃的），可直接被使用。
  • 自訂：用 /agents 互動建立，或手動在 .claude/agents/（專案）、~/.claude/agents/（個人）放 Markdown 檔。

檔案格式

---
name: code-explorer
description: 在大型程式碼庫中尋找相關檔案與實作方式。需要先了解現況、但不想塞滿主對話時使用。
tools: Read, Grep, Glob
model: haiku
---
你是程式碼探索員，只讀不改。
針對問題找出相關檔案，回報：
- 檔案路徑與一句話說明
- 關鍵函式與呼叫關係
不要貼大段程式碼；最多回報 10 個最相關的檔案。
欄位用途
name識別名稱
description何時該派它；主 agent 靠這句決定是否自動使用
tools可用工具；省略則繼承全部。審查與探索建議只給唯讀工具
model指定模型，或沿用主對話的模型

怎麼呼叫

> 用 code-explorer 找出所有處理訂單取消的程式碼

> 請同時啟動 3 個 subagent，分別審查正確性、安全、測試品質（互相獨立）

> 先用 subagent 探索現況，只回報結論，我再決定設計

什麼時候該用

適合不適合
大範圍搜尋與探索需要你與 agent 反覆討論的設計
獨立審查只改一兩個已知檔案的小任務
互不相依的平行工作步驟間強相依、要共享中間狀態
輸出很長但你只要結論結果需要完整細節才能判斷

設計原則

  • 一個 subagent 一個職責，description 寫清楚「何時用」。
  • 工具最小化：審查與探索只給唯讀。
  • 明確規定回報格式與長度，避免它把整包塞回主對話。
  • subagent 之間通常不會共享情境，需要的資訊要由主 agent 傳給它。

省 Token 技巧

  • 隔離就是省：把「讀一堆檔案」的成本關在它的情境，主對話保持精簡，之後每一輪都更便宜。
  • 探索與機械性工作用較小模型：model 欄位指定較省的模型。
  • 限制回報長度：「最多 10 項、只列路徑與一句話」。
  • 別濫用：每個 subagent 都有自己的啟動與讀檔成本；小任務直接做更省。
  • 平行不等於便宜：同時跑多個，總成本是相加的；它省的是時間，不一定省錢。
