MCP：連接外部系統

讓 agent 讀寫資料庫、Issue、行事曆、Trello、Slack 等工具。

MCP 是什麼

MCP（Model Context Protocol）是把外部服務接給 agent 的標準介面。一個 MCP 伺服器會提供一組「工具」（例如：查詢行程、建立卡片、搜尋郵件），agent 就能像呼叫內建工具一樣使用。

連線方式

類型說明範例
遠端（HTTP）連到服務商提供的網址，常需登入授權claude mcp add --transport http 名稱 網址
本機（stdio）在你電腦上啟動一個程式當伺服器claude mcp add 名稱 -- npx 某套件
管理做法
檢視與登入授權在對話中輸入 /mcp
範圍僅自己／此專案共用（.mcp.json 可入版控）／跨專案的個人設定
列出、移除claude mcp list、claude mcp remove 名稱

常見的工作用途

系統agent 能幫你做
行事曆查空檔、整理本週行程、起草會議邀請
Trello／Jira／Linear／Asana讀取待辦、整理看板、依會議結論建立卡片
Slack／Gmail彙整未讀、起草回覆（送出前由你確認）
Notion／Drive搜尋文件、更新紀錄
資料庫唯讀查詢協助除錯與分析
Issue 與 PR（GitHub 等）讀需求、建立與審閱 PR

實際整合行事曆與 Trello 的完整流程，見 06 進階工作流程。

安全與權限

第三方的 skill、plugin、MCP 伺服器都是「會被你的 agent 執行或讀取的外部程式與內容」，等同於安裝軟體。安裝前先看原始碼與來源、只授予必要權限；來自外部的內容（網頁、工單、郵件）也可能夾帶惡意指示（prompt injection），重要動作務必保留人工核准。
  • 讀寫分開授權：初期只開讀取；確認好用再開寫入。
  • 對外可見的動作永遠人工核准：寄信、邀請與會者、改別人的卡片、發訊息。
  • 資料庫用唯讀帳號，不要把正式環境的寫入權限交給 agent。
  • 憑證放在環境變數或祕密管理，不寫進被版控的設定檔。
  • 從 MCP 讀回的內容（郵件、工單、網頁）視為不可信資料，不是指令。

省 Token 技巧

  • 已連線的 MCP，其工具定義會佔用情境：工具越多佔得越多。用 /context 檢查，不用的直接停用或移除。
  • 依專案啟用：行事曆那類工具只在需要的工作區啟用，不要全域常開。
  • 查詢要有範圍：「本週、我的、狀態為進行中」，不要「列出全部」。
  • 要求摘要輸出：「只回報標題與截止日」，不要整張卡片的全文。
  • 能用腳本或 CLI 完成的固定工作，不必走 MCP：穩定且不耗推理成本。
