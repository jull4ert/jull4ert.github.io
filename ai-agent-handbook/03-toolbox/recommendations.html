推薦組合與常見坑

依情境挑選配置，並避開最常踩的雷。

依情境的建議配置

情境建議組合
個人起步精簡的 CLAUDE.md（指令 + 慣例）＋ 計畫模式習慣；先不裝擴充
日常開發CLAUDE.md ＋ 1～2 個自己的 skill（commit、審查）＋ 編輯後格式化 hook
重視品質上述 ＋ spec-reviewer / code-reviewer 兩個唯讀 subagent ＋ 交叉審查 skill（見 05）
團隊共用專案層級的 CLAUDE.md、skills、agents、hooks 納入版控；用 plugin 分享跨專案設定
非程式協作工作流行事曆／Trello／Slack 的 MCP（先唯讀）＋ 晨報、週報 skill ＋ 寫入前人工核准（見 06）
有合規要求最小權限、hook 攔截危險動作、MCP 用唯讀帳號、審查所有第三方擴充

建議的導入順序

  1. 先寫好 CLAUDE.md：投資報酬率最高。
  2. 把重複貼的指令做成 skill。
  3. 加上保證類的 hook（格式化、危險指令攔截）。
  4. 為審查與探索建立唯讀 subagent。
  5. 接上需要的 MCP，先唯讀。
  6. 最後才打包成 plugin 分享。

每加一樣，先觀察一週是否真的有幫助，再加下一樣。

常見的坑

坑後果解法
一次裝太多擴充常駐成本高、描述互相干擾、誤觸發逐一導入，定期清點；用 /context 檢查
CLAUDE.md 寫成百科全書遵守度下降、每輪都貴精簡，細節放 skill 或文件
用 CLAUDE.md 要求「一定要…」agent 偶爾會忘必須發生的事改用 hook
skill 描述太籠統亂觸發或不觸發寫清楚做什麼與何時用，實測調整
subagent 繼承所有工具審查者順手改檔限定唯讀工具
MCP 全域開、全部寫入權限誤操作、情境被工具定義佔滿專案啟用、先唯讀、寫入需核准
未審查就裝第三方擴充安全風險先看原始碼與來源
hook 太慢或會失敗每次操作都卡住保持快速，失敗要有明確訊息

定期保養

  • 每月清點：哪些 skill、agent、MCP 已沒在用？
  • 把 agent 反覆犯的錯，對應補進 CLAUDE.md 或 skill，並刪除已不需要的規則。
  • 擴充更新後重新實測關鍵流程。

省 Token 技巧

項目做法
盤點常駐成本/context 看 CLAUDE.md、skill、MCP 各佔多少
停用而非累積不用的 MCP、skill 先停用，要用再開
保證用 hook、判斷用 skill前者無推理成本，後者按需載入
探索與審查用 subagent 並限制回報主對話保持精簡
