Skills 與 Plugins

安裝、管理、挑選；以及怎麼把自己的流程打包分享。

Skills：怎麼來

來源做法
自己寫在 .claude/skills/名稱/SKILL.md（專案）或 ~/.claude/skills/（個人）建立，寫法見 02 SKILL.md
團隊共用放進專案的 .claude/skills/ 並納入版控，clone 就有
別人做好的透過 plugin 安裝，或直接取得資料夾放到上述位置

Plugins：把整套設定打包

Plugin 可以同時包含自訂指令、subagent、skill、hooks 與 MCP 設定，一次安裝全部啟用，適合團隊統一工作方式。

操作範例
開啟管理介面/plugin
加入來源（marketplace）/plugin marketplace add 擁有者/倉庫
安裝/plugin install 外掛名@來源名
停用／移除在 /plugin 介面操作

挑選與評估

檢查項目問自己
來源是官方、知名作者，還是不明來源？
內容讀過它的 SKILL.md、hooks、腳本嗎？有沒有下載或外傳資料的指令？
權限它要求哪些工具權限？是否超出用途？
維護最近有更新嗎？有人在用嗎？
重疊是否與你已有的 skill 功能重複、描述衝突？
成本它的描述與指令會常駐多少情境？
第三方的 skill、plugin、MCP 伺服器都是「會被你的 agent 執行或讀取的外部程式與內容」，等同於安裝軟體。安裝前先看原始碼與來源、只授予必要權限；來自外部的內容（網頁、工單、郵件）也可能夾帶惡意指示（prompt injection），重要動作務必保留人工核准。

省 Token 技巧

  • 每裝一個 skill，就多一段常駐描述：只留常用的，不用的移除或停用。
  • 描述精簡且明確：太籠統會誤觸發，載入不需要的全文就是浪費。
  • plugin 一次帶來多個元件：安裝前看清楚帶了哪些 skill、agent、MCP，用不到的關掉。
  • 用 /context 檢查哪些擴充佔用了多少情境。
  • 安裝或評估外掛時，可用 claude plugin details 名稱 查看它的元件清單與預估 token 成本（已在本機 --help 確認此指令存在）。
