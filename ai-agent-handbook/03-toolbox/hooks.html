Hooks：保證會發生的自動化

在特定事件自動執行指令，不依賴 agent 記不記得。

它是什麼

Hook 是你在設定檔中登記的 shell 指令，由 Claude Code 在特定事件觸發執行。因為由系統執行而非模型決定，所以是「保證」。

常用事件

事件時機典型用途
PreToolUse工具執行前攔截危險指令、保護特定檔案
PostToolUse工具執行後編輯後自動格式化、跑 lint
UserPromptSubmit你送出提示時自動補充固定脈絡
Stopagent 完成回應時通知你、紀錄、最後檢查
SessionStart對話開始時載入環境資訊
Notification需要你注意時桌面通知、提示音

設定位置

檔案範圍
~/.claude/settings.json你的所有專案
.claude/settings.json此專案，可入版控、團隊共用
.claude/settings.local.json此專案，只有自己

也可用 /hooks 互動管理。

範例一：編輯後自動格式化

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "./scripts/format-changed.sh" }
        ]
      }
    ]
  }
}

Hook 會透過標準輸入收到 JSON，內含工具名稱與參數（例如被編輯的檔案路徑），腳本自行解析後處理。

範例二：攔截危險指令

#!/usr/bin/env bash
# scripts/block-danger.sh：由 PreToolUse（matcher: Bash）呼叫
input=$(cat)
cmd=$(echo "$input" | jq -r '.tool_input.command')
if echo "$cmd" | grep -Eq 'rm -rf|git push --force|DROP TABLE'; then
  echo "已攔截高風險指令，請改用更安全的做法或由人工執行" >&2
  exit 2
fi
exit 0

以特定結束碼（通常 2）回應，表示阻擋該動作，並把標準錯誤輸出的訊息回饋給 agent，讓它知道為什麼被擋。

範例三：完成時通知

長任務跑很久時，用 Stop 或 Notification 事件發出桌面通知，你就不必盯著畫面。

設計原則

  • 快：hook 會卡住流程，不要放耗時指令。
  • 只做確定性的事：格式化、阻擋、通知；需要判斷力的交給 agent 或 skill。
  • 失敗要有訊息：被擋時說清楚原因與替代做法。
  • 注意安全：hook 以你的權限執行任意指令，來自他人的設定檔要先看過。
  • 先小範圍測試：用個人設定檔試，再提交到專案。

省 Token 技巧

  • 用 hook 取代「請記得…」的提示：自動格式化不必每次在指令裡叮嚀，也不必讓 agent 手動執行再讀輸出。
  • 過濾 hook 輸出：回饋給 agent 的訊息要短，只說被擋的原因。
  • 攔截於事前：在危險或無意義的動作發生前擋下，避免之後的修復對話。
