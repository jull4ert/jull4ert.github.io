治理與風險

讓 agent 又快又安全：資料、權限、成本、品質，以及知道什麼時候不該用。

前面各區教你怎麼把 agent 用強。這一區處理另一面：用強之後，什麼會出事，以及怎麼把風險控制在可接受的範圍。

五個風險面向

面向典型問題頁面
資料機密、個資、客戶程式碼被送出或寫進文件資料與機密
權限誤刪、誤發、被惡意內容誘導執行危險動作權限與防護
成本用量失控、長對話、無謂重做成本控管
品質看起來對、實際有錯；越用越依賴卻不知好壞品質評估
適用性把不該交給 agent 的事交給它何時不該用
組織團隊各用各的、沒有規範與責任歸屬團隊導入與規範

頁面

四個核心原則

  1. 最小權限：只給完成任務所需的資料與工具。
  2. 人在迴圈：不可逆、對外、涉及金錢與個資的動作，由人核准。
  3. 可追溯：做了什麼、為什麼、依據什麼，要查得到。
  4. 責任在人：agent 的產出由使用它的人負責，不能推給工具。
若你的工作涉及為客戶交付軟體，也請對照 資安交付手冊：它處理的是交付物本身的資安，本區處理的是「使用 agent 的過程」的風險。
本頁為一般性的實務建議，不構成法律意見。資料保存、模型訓練使用、地區合規等條款依你使用的方案與合約而異，請以供應商最新條款與你的法務、資安負責人意見為準。設定語法與欄位以官方文件為準。
