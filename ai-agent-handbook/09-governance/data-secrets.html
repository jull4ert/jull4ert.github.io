資料與機密

哪些東西不該進對話、不該被讀到，以及怎麼把風險降到最低。

先搞清楚資料會去哪裡

你輸入的內容、agent 讀取的檔案、工具回傳的結果，都會作為情境送往模型服務。因此「agent 能讀到的」就等於「可能被送出的」。

問題你要弄清楚
資料保存供應商保存多久？可否關閉？依你的方案與合約而定
訓練使用你的內容是否可能用於模型訓練？商用與個人方案條款不同
區域與合規資料是否能出境？客戶合約或法規有沒有限制？
第三方你連接的 MCP 與外掛，會把資料再送去哪？

資料分級：什麼可以給 agent

等級例子建議
公開開源程式碼、公開文件可自由使用
內部公司程式碼、內部文件在核可的工具與方案下使用
機密金鑰、密碼、憑證、客戶合約不讓 agent 讀取；用祕密管理
個資與受管制資料客戶個資、金融、醫療預設禁止；需要時用去識別化的測試資料，並取得授權

實務做法

  • 機密不放專案檔案：金鑰用環境變數或祕密管理服務；.env 不提交、也不讓 agent 讀。
  • 用權限規則擋住敏感檔案：在設定檔的 deny 規則列出不可讀取的路徑。
  • 用測試資料開發：用假資料或去識別化資料，不連正式資料庫。
  • 不要貼完整 log 與資料庫匯出：先遮蔽個資與憑證。
  • 連線用唯讀、低權限帳號：資料庫、雲端、API 都一樣。
  • 檢查 agent 產出的檔案：避免它把金鑰、個資寫進文件、測試資料或 commit。
  • 提交前掃描：用機密掃描工具（見資安交付手冊）擋在 commit 與 CI。
// .claude/settings.json（示意：禁止讀取敏感檔案）
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Read(./**/appsettings.Production.json)"
    ]
  }
}
deny 規則的語法與涵蓋範圍會隨版本調整，請以官方文件為準；它是防線之一，不是唯一防線，仍要把機密放在 agent 取不到的地方。

萬一貼出去了

  1. 視為已洩漏：立即撤銷並更換該金鑰或密碼。
  2. 確認有沒有被寫進 commit、log、文件；有的話一併清除歷史並更換。
  3. 評估影響範圍（誰能用這把金鑰、能做什麼）。
  4. 依公司與合約流程通報。
  5. 補上預防：加入 deny 規則、掃描、教育。

省 Token 技巧

  • 遮蔽與精簡資料同時降低風險與成本：只給 agent 需要的欄位與片段，不貼整份匯出。
  • 用 deny 規則擋掉大型無關檔案：例如建置產物、套件目錄、大型資料檔，避免誤讀。
本頁為一般性的實務建議，不構成法律意見。資料保存、模型訓練使用、地區合規等條款依你使用的方案與合約而異，請以供應商最新條款與你的法務、資安負責人意見為準。設定語法與欄位以官方文件為準。
