何時不該用 agent

知道界線，和知道怎麼用一樣重要。

四個快速問題

問題答「否」時
我能驗證結果嗎？無法判斷對錯的領域，產出再漂亮也不能信
出錯可以還原嗎？不可逆的動作由人親自做，或加強核准與備份
風險我承擔得起嗎？涉及人身安全、大額金錢、法律責任，要人主導
我有能力審它嗎？你看不懂的東西，不要在正式環境使用

不適合或需特別謹慎的情境

情境原因替代做法
處理受管制或機密資料資料外送與合規風險去識別化、離線方案、取得授權後在核可環境使用
直接操作正式環境不可逆、影響範圍大由人執行；agent 只產生指令與檢查清單
需要法律、醫療、財務的最終判斷需要有資格者負責agent 做資料整理與初稿，由專業人員決定
安全關鍵程式（金流、權限、加密）細微錯誤後果嚴重人主導設計與審查，agent 輔助；多重交叉審查加專家把關
方向與品味的決定需要你的判斷與價值觀agent 提供選項與取捨，你決定
你想學會的技能全部交出去會讓自己學不到先自己做，再讓 agent 審、解釋
極小的修改描述與審查的成本高於直接改自己改
需求完全不明、連你也說不清agent 會自行腦補先釐清需求，或用訪談（見 04）
極度依賴最新資訊或內部未公開知識模型知識有時效限制提供文件與資料，或查證後再用

「可以用，但要加關卡」的情境

  • 資料庫結構變更與資料遷移：agent 起草，人審查，在測試環境演練。
  • 對外溝通（信件、公告、客戶回覆）：agent 起草，人修改後送出。
  • 部署與回滾：agent 準備清單與腳本，人觸發。
  • 刪除類操作：先列清單，人確認，再執行，並有備份。

警訊：你過度依賴了

  • 你不再讀 diff，直接接受。
  • 你說不清楚程式為什麼這樣寫。
  • 驗證都靠 agent 自己回報，你沒親手跑過。
  • 出錯時不知道從哪裡查起。

出現這些訊號時，放慢：重新讀 diff、親手跑一次關鍵流程、把關卡補回來。

本頁為一般性的實務建議，不構成法律意見。資料保存、模型訓練使用、地區合規等條款依你使用的方案與合約而異，請以供應商最新條款與你的法務、資安負責人意見為準。設定語法與欄位以官方文件為準。
