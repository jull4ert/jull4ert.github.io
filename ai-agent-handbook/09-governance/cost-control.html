成本控管

知道錢花在哪、設上限、持續優化。這一頁也是全手冊「省 Token」技巧的總整理。

成本結構

項目說明
輸入每一輪重送的對話歷史、檔案、工具輸出、常駐文件（有快取折扣，但仍是大宗）
輸出模型產生的文字與程式碼，單價通常較高
模型越大越貴；簡單任務用小模型
倍增器subagent、多視角審查、平行任務、排程頻率都會相乘
浪費方向錯重做、長對話、無謂探索、重複載入

量測

  • 對話中用 /cost 看本次用量、/context 看情境佔用。
  • 團隊用量請看供應商的用量儀表板或帳務報表；部分版本提供遙測與監控的整合選項。
  • 記錄「哪類任務花多少」，才知道優化哪裡。

上限與預算

層面做法
個人／團隊設定用量上限或預算提醒（依方案提供的功能）
自動化--max-turns、--max-budget-usd（只搭配 -p）、逾時、頻率上限；失敗不無限重試
CI觸發條件精準、只審 diff、草稿 PR 不審
金鑰為自動化使用獨立金鑰，可單獨設限與撤銷

省 Token 技巧總索引

省法分散在各主題中，隨流程出現。依影響大小，優先做這幾件：

優先序做法詳見
1任務完成就 /clear，一個對話一件事模式與指令
2用計畫模式先對齊，避免整包重做寫出好指令
3精簡常駐文件（CLAUDE.md、skill 描述、MCP）CLAUDE.md、工具箱建議
4探索與審查交給 subagent，限制回報長度與模型Subagent
5階段產出存檔，換對話接力任務拆解
6過濾工具輸出，只看失敗與摘要實作
7依風險決定審查輪數與視角程式碼審查
8排程先用腳本判斷有沒有事排程

首頁的「省 Token 速查」列出所有相關頁面。

成本與價值的判斷

  • 比較的對象是人的時間與返工成本，不是零。一次省下半天的任務，多花一些 Token 通常划算。
  • 真正該砍的是浪費：重做、失控的迴圈、無人看的排程。
  • 省 Token 不該犧牲驗證與審查；把錢省在流程，不要省在品質關卡。

常見的成本陷阱

陷阱解法
超長對話一路用到底階段結束 /clear，用檔案接力
每個小事都派 subagent 或多視角審查依風險分級
排程每小時跑，沒人看降頻、沒事不通知、先腳本判斷
CI 對每個 commit 都完整審查只審 PR、只審 diff、同 commit 不重審
失敗後無限重試輪數上限，三次未果就停下回報
全部用最大模型依任務複雜度選模型
