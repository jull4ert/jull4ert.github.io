交叉審查：找出盲點

讓多個 agent 從不同角度互相挑戰，抓出你和單一 agent 都看不到的需求與程式碼盲點。

單一 agent 寫完又自己檢查，常常會「確認自己是對的」。交叉審查的目的，是刻意製造獨立性：換一個乾淨的情境、換一個角色、換一份資訊，讓審查者有機會看到作者看不到的東西。

核心流程

需求 ─► [需求審查] 反方角色 / 事前驗屍 / 缺漏情境 │ 修正規格 ▼ 規格 ─► 實作 ─► [程式碼審查] 獨立 subagent / 多視角並行 / 對抗式驗證 │ 每項發現都要附證據（測試、重現步驟） ▼ [彙整與裁決] 去重、分級、採納或駁回、記錄原因 │ ▼ 重複出現的盲點 → 寫回 CLAUDE.md / 審查 skill（讓下次更早抓到）

五個頁面

三個最重要的原則

  1. 審查者不能看到作者的結論。只給它規格與產出，不給「我覺得這樣沒問題」，避免被帶著走。
  2. 每個發現都要有證據。沒有證據的意見只能算「疑問」，不能算「缺陷」。
  3. 人做最後裁決。agent 負責找，你負責判斷哪些值得處理。
