情境

Razor 與 Vue 的語法衝突

在 .cshtml 中，@ 是 Razor 的語法起點，所以 Vue 的縮寫 @click 會被 Razor 當成程式碼解析而出錯。處理方式：

  • 改用完整寫法 v-on:click、v-bind:key（本專案採用）。
  • 或用 @@click 跳脫成一個 @。
  • 或把 Vue 模板放進 .js / .vue 檔案，不經過 Razor。

{{ }} 插值則不受影響。

參考解答（formatDate，已實際執行驗證） 
function formatDate(iso) {
  if (!iso) {
    return "";
  }
  return new Intl.DateTimeFormat("sv-SE", { timeZone: "Asia/Taipei" }).format(new Date(iso));
}

測試（與執行機器的時區無關，因為明確指定時區）：

test("formatDate 以台灣時區顯示", () => {
  assert.strictEqual(formatDate("2026-10-01T17:00:00Z"), "2026-10-02");
  assert.strictEqual(formatDate("2026-10-01T01:30:00Z"), "2026-10-01");
});

test("formatDate 空值回傳空字串", () => {
  assert.strictEqual(formatDate(null), "");
});

「sv-SE」語系會輸出 YYYY-MM-DD 的格式，是一個常見的小技巧；已在 Node 實測。

參考解答（空狀態與錯誤訊息）

orders-app.js：data 加入 message: ""；load 與 cancel 改為：

async load() {
  this.message = "";
  const query = new URLSearchParams({ departmentId: this.departmentId });
  if (this.status) { query.append("status", this.status); }
  const response = await fetch("/api/orders?" + query);
  if (!response.ok) {
    const body = await response.json().catch(() => ({}));
    this.message = body.error || "載入失敗";
    this.orders = [];
    return;
  }
  this.orders = await response.json();
},
async cancel(order) {
  const response = await fetch("/api/orders/" + order.id + "/cancel?departmentId=" + this.departmentId, { method: "POST" });
  if (!response.ok) {
    const body = await response.json().catch(() => ({}));
    this.message = body.error || "取消失敗";
    return;
  }
  await this.load();
}

Index.cshtml 加入：

<p v-if="message" class="error">{{ message }}</p>
...（表格之後）
<p v-if="!orders.length && !message">查無資料</p>
