  • 有決策紀錄與規格，且時區的決定有寫下來。
  • 需求審查至少找出一個規格缺漏並處理。

  • 證據表中每條都有證據，如有不通過也誠實標示。
  • 前端日期輸入能實際操作，起日晚於迄日時使用者能看到錯誤。
參考解答（後端，已實際執行驗證）

OrderService.List：

public IReadOnlyList<Order> List(
    int departmentId,
    OrderStatus? status = null,
    DateTime? from = null,
    DateTime? to = null)
{
    var query = repository.GetAll().Where(o => o.DepartmentId == departmentId);

    if (status.HasValue)
    {
        query = query.Where(o => o.Status == status.Value);
    }

    if (from.HasValue)
    {
        query = query.Where(o => o.CreatedAt >= from.Value.Date);
    }

    if (to.HasValue)
    {
        query = query.Where(o => o.CreatedAt < to.Value.Date.AddDays(1));
    }

    return query.OrderByDescending(o => o.CreatedAt).ToList();
}

OrdersApiController.Get：

[HttpGet]
public IActionResult Get(
    [FromQuery] int departmentId,
    [FromQuery] OrderStatus? status,
    [FromQuery] DateTime? from,
    [FromQuery] DateTime? to)
{
    if (from.HasValue && to.HasValue && from.Value.Date > to.Value.Date)
    {
        return BadRequest(new { error = "起日不得晚於迄日" });
    }

    return Ok(service.List(departmentId, status, from, to));
}

測試：

[Fact]
public void List_WithDateRange_IncludesBothEndDays()
{
    var orders = CreateService().List(
        departmentId: 1,
        from: new DateTime(2026, 10, 3),
        to: new DateTime(2026, 10, 12));

    Assert.Equal(new[] { 4, 3, 2 }, orders.Select(o => o.Id).ToArray());
}

此解答已實際執行：加入 3 個日期測試後全數通過，API 對起日晚於迄日回 400。

前端的錯誤顯示（起日晚於迄日）在 Lab 5 處理。

時區的決定與取捨

練習解答採用「依資料的建立時間（UTC）切日期」，簡單但可能與使用者感受的日期差一天（台灣為 UTC+8，早上 8 點前建立的訂單，UTC 日期會是前一天）。真實專案請依客服實際使用情境決定，並寫進規格。
