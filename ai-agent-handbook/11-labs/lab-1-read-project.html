Lab 1：讀懂專案

用 agent 當導遊讀懂陌生專案，並驗證它說的是不是對的。

預計時間：45～60 分鐘　模式：全程唯讀（計畫模式）

目標

  • 能說出「按下取消按鈕」之後，請求經過哪些檔案。
  • 產出一份自己整理的 docs/notes/architecture.md。
  • 練習查證 agent 的說法，而不是直接相信。

步驟

  1. 切到計畫模式（Shift+Tab），確保它不會修改檔案。
  2. 讓 agent 導覽： 
    > 我是新人。請帶我導覽這個專案：
> 1. 目錄結構各管什麼
> 2. 從使用者在畫面按下「取消」開始，列出經過的檔案與方法，附檔案路徑
> 3. 資料存在哪裡？重啟後會怎樣？
> 4. 最值得先讀的三個檔案
> 先不要修改任何檔案。
  3. 查證：自己打開它提到的檔案，逐一確認「這個檔案真的有這個方法嗎？」
  4. 請它把導覽整理成 docs/notes/architecture.md，你修改成自己的話。
  5. 反問一題：「如果 orderId 不存在，Cancel 會回傳什麼？前端會看到什麼？」並用程式碼驗證。

預期結果

請求路徑大致為：

Views/Orders/Index.cshtml（按鈕 v-on:click="cancel(o)"）
  → wwwroot/js/orders-app.js 的 cancel()：POST /api/orders/{id}/cancel?departmentId=…
  → Controllers/Api/OrdersApiController.cs 的 Cancel
  → Services/OrderService.cs 的 Cancel
  → Data/InMemoryOrderRepository.cs 的 Get / Update（資料在記憶體，重啟會重置）

檢核

  • 我能不看筆記說出上面的路徑。
  • 我驗證過 agent 的說法，並找到至少一處它說得不精確或我原先誤解的地方。
  • 我的筆記是用自己的話寫的。
  • agent 沒有修改任何檔案（git status 乾淨）。
參考觀察（看完你自己的結果再打開）
  • 前端的 cancel() 不檢查回應是否成功，失敗時使用者什麼也看不到。（Lab 5 會處理）
  • API 的 departmentId 來自查詢字串，由前端提供，不是從登入身分取得。（Lab 6 會討論）
  • Repository 是 Singleton 的記憶體清單，重啟即重置，也不是執行緒安全。
