Lab 2：修 bug（先寫失敗的測試）

取消已出貨的訂單不該成功。先重現、先讓測試失敗，再修，再證明修好了。

預計時間：45～60 分鐘　分支：lab2-fix

情境

客服回報：「已出貨的訂單還能按取消，而且會變成已取消。」規則是：已出貨的訂單不能取消。

目標

  • 用實際操作重現問題。
  • 先寫會失敗的測試，確認失敗，再修，再確認通過。
  • 用 diff 確認修改範圍最小。

步驟

  1. 重現：啟動網站，在部門 1 的列表對「已出貨」的訂單 2 按取消，觀察狀態被改掉。或用 API： 
    curl -X POST "http://localhost:5000/api/orders/2/cancel?departmentId=1" -i
  2. 讓 agent 先找根因，不要修改： 
    > 已出貨（Shipped）的訂單目前可以被取消，這是錯的。
> 重現方式：POST /api/orders/2/cancel?departmentId=1。
> 請先閱讀 OrderService.Cancel，找出根因並說明，現在不要改檔案。
  3. 先寫失敗的測試： 
    > 在 tests/OrderDemo.Tests/OrderServiceTests.cs 新增一個測試：
> 取消已出貨的訂單 2 應失敗，錯誤訊息為「已出貨的訂單不能取消」。
> 只加測試，不要修改正式程式碼。執行 dotnet test 並貼出結果，我要看到它失敗。
  4. 修正： 
    > 現在修正 OrderService.Cancel，讓這個測試通過。只改這個方法，不要動其他檔案。
> 執行全部測試並貼出結果。
  5. 用 git diff 檢查：正式程式只改了一處嗎？
  6. 再實際操作一次網站，確認已出貨訂單取消時被拒絕。
  7. commit。

預期結果

階段預期輸出
寫完測試後（修正前）失敗 1、通過 6、總計 7
修正後已通過！失敗 0、通過 7
API 對訂單 2 取消HTTP 400，內容 {"error":"已出貨的訂單不能取消"}

檢核

  • 我親眼看到測試先失敗，原因就是我要修的 bug。
  • 正式程式碼的 diff 很小（約 5 行以內）。
  • agent 沒有為了通過測試而修改測試。
  • 我實際操作了網站（或 API）驗證。
參考解答

測試：

[Fact]
public void Cancel_ShippedOrder_Fails()
{
    var result = CreateService().Cancel(orderId: 2, departmentId: 1);

    Assert.False(result.Success);
    Assert.Equal("已出貨的訂單不能取消", result.Error);
}

修正（在 Cancel 設定狀態之前加入）：

if (order.Status == OrderStatus.Shipped)
{
    return CancelResult.Fail("已出貨的訂單不能取消");
}

此解答已實際執行驗證：修正前測試失敗（失敗 1、通過 6），修正後全部通過（通過 7）。

如果 agent 做了這些事，要警覺
  • 順手重構整個 Service，或改了其他方法。
  • 先改正式程式，再寫「剛好通過」的測試。
  • 把「已取消」的測試期望值改掉。
