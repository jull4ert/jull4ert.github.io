新手專區：四週學習路徑

給剛開始的工程師：照這個順序讀、照這些練習做，四週後能和 AI agent 協作產出。

這份手冊很完整，但不是用來從頭讀到尾的。如果你是初階工程師，請照這一頁的路徑走：每週有目標、要讀的頁面、要做的練習和檢核點。

本章範例以 ASP.NET Core MVC（.NET 8）＋ Vue 3，前後端在同一個 .NET 專案為基準。若你的專案是 .NET Framework 的 ASP.NET MVC 5，觀念與流程相同，但建置與測試指令（例如 MSBuild、vstest）、專案檔格式與設定檔不同，請在你的 CLAUDE.md 中寫清楚。

先講結論：你要練成什麼樣子

四週後，你應該能做到：

  • 拿到一個小需求，能和 agent 一起釐清、規格化、實作、測試、驗證，而且說得出每個決定的理由。
  • 能判斷 agent 的產出對不對、有沒有多做，看不懂時知道怎麼查證。
  • 能把專案慣例寫進 CLAUDE.md，讓 agent 照你的團隊風格做事。
  • 知道哪些事不能交給 agent，並在該找人看的時候找人。

每天 1 小時的節奏

時間做什麼
15 分鐘讀當天要讀的頁面（只讀「重點」，不必背）
35 分鐘在練習專案上動手做對應的練習
10 分鐘寫學習紀錄：今天做了什麼、agent 哪裡做錯、我學到什麼

四週路徑

週目標先讀練習檢核點
第 1 週
建立基礎		會啟動 agent、問答、讀懂專案；補齊 git 與測試的基本功 前置知識、00 基礎觀念、01 入門 Lab 0、Lab 1 能用自己的話說明練習專案的一個請求如何從 Vue 走到資料；dotnet test 全綠
第 2 週
小任務		修 bug、補測試，並學會驗證 agent 的產出 驗證看不懂的程式、04 實作、04 驗證 Lab 2、Lab 3 先寫失敗的測試再修；能說出「怎麼證明它修好了」
第 3 週
完整流程		從需求到交付，並用交叉審查找盲點 04 全部、05 全部、把 agent 當老師 Lab 4、Lab 5、Lab 6 有規格、計畫、證據表、審查裁決表四份產出
第 4 週
變成習慣		把慣例寫成文件與 skill，獨立完成一個小需求 02 文件、03 工具箱、過度信任的警訊 Lab 7、Lab 8 通過能力檢核第 3 級

先不要讀的

頁面原因什麼時候讀
06 進階工作流程需要先熟悉單一任務的協作第 4 週之後
07 社群經驗多數偏個人風格，容易混淆有自己的做法後再比較
09 治理與風險的團隊導入偏管理層面需要時；但「資料與機密」、「權限與防護」第 1 週就該讀

卡住的時候

  1. 把問題縮小：先回到前一個能運作的狀態（git restore 或 /rewind）。
  2. 把你預期的、實際的、錯誤訊息，原封不動貼給 agent，請它「先解釋原因，不要改檔案」。
  3. 查速查表與術語表。
  4. 超過 30 分鐘沒有進展，就問同事；不要獨自和 agent 反覆循環。
