1. Marmelab：Claude Code Tips I Wish I'd Had From Day One

Claude Code Tips I Wish I'd Had From Day One

來源：公司部落格；作者 Caroline Schneider（Marmelab）；2026-04-24。團隊數月日常使用的經驗報告，文末含公司產品連結與宣傳。

重點

  • 複雜任務先用計畫模式，讓假設錯誤早點被抓到。
  • 一次只要第一步，審過再要下一步。
  • 走錯方向時用 /rewind（或連按兩次 Esc）或 /clear，不要在同一情境裡「追加修正」，那會汙染後續嘗試。
  • agent 引入 bug 時：先讓它調查、把教訓寫進專案文件，再修。
  • 用 @路徑 引用檔案、用 ! 執行 shell 指令。
  • CLAUDE.md 保持在約 200 行內；共用內容放 AGENTS.md，再用 @AGENTS.md 匯入。

可以直接套用

  • 01 模式與指令、02 AGENTS.md 已涵蓋；「把教訓寫進文件」呼應 04 交付的回饋

作者自己說的限制

  • 屬團隊個人經驗：其中「約 40 萬 token 後品質下降」、對 worktree 的懷疑等是經驗之談，不是可驗證的事實。
  • 推薦的第三方工具（如 Context7 等）不是 Claude Code 的功能，採用前請另行評估。

2. ykdojo：claude-code-tips（GitHub）

45+ Claude Code Tips: From Basics to Advanced

來源：GitHub 倉庫 README；作者帳號 ykdojo；未標示發布日期。第一人稱的個人經驗兼參考文件。

重點

  • 把大問題拆小，一直拆到每塊都能解。
  • 主動壓縮情境；重開前請 Claude 寫一份 HANDOFF.md 交接。
  • 讓 agent 能完成「寫、測、驗」的循環，才能放心讓它自主作業。
  • 自訂狀態列顯示模型、目錄、分支與 Token 用量，方便隨時掌握。
  • 讓 agent 處理 git 與 GitHub CLI，但以草稿 PR 先讓你審。

可以直接套用

  • 交接檔與主動壓縮 → 01 模式與指令的省 Token、04 計畫檔接力
  • 寫測驗循環 → 04 驗證

作者自己說的限制

  • 是否允許自動 pull/push、關閉自動壓縮、語音輸入、偏好 Playwright 等都是作者個人設定。
  • 我只完整讀到前段；後段內容（例如自動模式相關的設定）未逐字核對，採用前請回原文確認。
