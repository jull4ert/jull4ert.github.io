Best practices for Claude Code

來源：官方文件。頁面未標示發布或更新日期。

重點

  • 只寫 Claude 讀程式碼也無法得知的事；問自己「它找得到嗎？它會去找嗎？」
  • 指令要具體：指明檔案、描述症狀、說明「修好」的樣子；可用 @ 引用、截圖或管線輸入補脈絡。
  • 先讓 Claude 訪談你直到能寫出規格，再開新對話依規格檔實作。
  • CLAUDE.md 保持精簡：只放測試、型別檢查、lint 指令、容易誤導的位置、未成文的決定；個人偏好放 CLAUDE.local.md 並加入 gitignore；記憶指南建議在 200 行內。
  • 路徑專屬的規則可放 .claude/rules/ 並用 paths: 限定，只在相關時載入。
  • 團隊程序（發版、runbook）放進 skill；有副作用的流程設定 disable-model-invocation: true。
  • 給 Claude 一個會回報通過或失敗的檢查指令，並要求貼出輸出作為證據才接受「完成」。
  • 用 Stop hook 搭配以結束碼 2 退出的檢查（例如型別檢查），強制它做到通過為止；用 PostToolUse hook 做格式化。
  • 不可讀的檔案用 deny 規則（在所有權限模式都有效）；需要作業系統層級限制時用 /sandbox。
  • 用 /effort 調整思考深度；無人值守可用 claude -p 搭配 --max-turns 等限制。
