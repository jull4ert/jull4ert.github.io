Context Engineering for Coding Agents

來源：martinfowler.com「Exploring Gen AI」系列；作者 Birgitta Böckeler（Thoughtworks）；2026-02-05。

重點

  • 把情境分成兩層：可重用的提示（指示與指引），以及情境介面（工具、MCP、skills）。
  • 情境越小越好：不要一開始就塞滿規則，邊用邊逐步加。
  • 用 /context 這類功能看清楚誰佔了多少空間。
  • 依「誰決定載入」來選機制：LLM 決定（skills、MCP）、人決定（斜線指令）、agent 軟體決定（hooks）。
  • 只把「常被重複、整個專案通用」的慣例放 CLAUDE.md；與檔案相關的指引改用路徑範圍的規則。
  • 必須每次都發生的事（例如編輯後格式化）用 hook，因為它是確定性的。
  • 大任務或需要「第二意見」時用 subagent，甚至以不同模型審查。
  • 既有程式碼本身就是情境，AI 友善的程式碼設計會讓 agent 表現更好。
  • 情境設定在團隊內分享、逐步累積，而不是照抄陌生人的。

可以直接套用

  • 誰決定載入的分類，可對照 → 03 五種擴充的決策表
  • 情境要小、要量測 → 00 情境視窗、09 成本控管
  • 不同模型審查 → 05 為什麼要交叉審查

作者自己說的限制

  • 「控制的錯覺」：最終仍由 LLM 的詮釋決定，我們永遠無法完全確定它會載入或遵守什麼。
  • 「情境工程沒有單元測試」：只能靠使用經驗判斷好壞。
  • 情境過多會讓 agent 效果下降；分享的設定容易過度工程、彼此矛盾。
  • 功能清單反映 2026 年 1 月的 Claude Code，作者預期之後會收斂；文中指出斜線指令已被 skills 取代。
