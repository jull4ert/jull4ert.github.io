食譜：在 MVC 專案中使用 Vue

同一個 .NET 專案裡放 Vue：載入方式、Razor 衝突、資料傳遞、防偽造權杖與測試。

兩種常見做法

做法特色適合
以 CDN 或靜態檔載入 Vue，在頁面上掛載不需 Node 建置；單檔頁面小應用；本手冊練習專案採用既有 MVC 頁面逐步加入互動
Vite（或其他打包工具）＋單檔元件（.vue），建置輸出到 wwwroot可用元件、模組、TypeScript、前端測試；需要 Node前端較複雜、有專人維護

無論哪種，請在 CLAUDE.md 寫清楚前端怎麼建置、怎麼測試、檔案放哪，agent 才不會亂放。

陷阱一：Razor 的 @ 與 Vue 縮寫衝突

寫法結果
@click="save"（寫在 .cshtml）Razor 把 @click 當程式碼，編譯錯誤或行為怪異
v-on:click="save"正確
@@click="save"Razor 輸出一個 @，也正確
寫在 .js 或 .vue 檔不經過 Razor，可用任何寫法

把這一條寫進 CLAUDE.md，agent 才不會每次都踩。

陷阱二：怎麼把伺服器資料交給前端

  • 首選：頁面載入後，由前端呼叫 JSON API 取得（本專案做法）。
  • 如果要在頁面直接內嵌初始資料，請用框架提供的 JSON 序列化輸出，不要自己用字串拼接 JSON 或把使用者輸入直接寫進 <script>，否則有 XSS 風險。請對照官方文件確認編碼行為。
  • 也不要把機密（金鑰、內部網址）輸出到前端。

陷阱三：POST 與防偽造權杖（CSRF）

若你的站台使用 Cookie 登入，對伺服器的 POST／PUT／DELETE 需要防偽造機制。傳統 MVC 表單用 @Html.AntiForgeryToken() 與 [ValidateAntiForgeryToken]；用 fetch 呼叫 API 時，要把權杖放進請求標頭。實作細節因版本與設定而異，請讓 agent 先讀你專案現有的做法與官方文件，再提出方案，並由你確認。

陷阱四：快取與路徑

  • CDN 或靜態檔更新後，瀏覽器可能仍用舊檔案；確認版本參數或檔名策略。
  • CDN 版本請鎖定版本號，避免版本自動變動。
  • 靜態檔路徑在不同部署方式（子應用程式、虛擬目錄）可能不同，用 ~/ 與 Url.Content 處理。

測試前端的分層做法

層做法
純函式（格式化、計算）抽成獨立檔案，用 Node 內建測試（本專案：node --test）
元件行為使用 Vite 專案時搭配 Vitest 等工具
整個流程手動操作，或端對端測試工具

提示範例

> 我要在 @src/OrderDemo.Web/Views/Orders/Index.cshtml 加一個「訂單詳情」側邊欄。
> 限制：
> - 不引入建置工具，延續目前的 Vue CDN 方式
> - 事件一律用 v-on: 寫法
> - 資料用 fetch 呼叫 /api/orders/{id}，不要把資料內嵌在頁面
> - 格式化相關的純函式放 order-utils.js 並補 node 測試
> 先給計畫，等我確認再動手。

檢查清單

  • .cshtml 中沒有 @click 這類縮寫。
  • 沒有字串拼接 JSON 或把使用者輸入寫進 script。
  • POST 有防偽造機制（或確認不適用）。
  • 純函式有測試，且不依賴機器時區。
  • 我在瀏覽器實際操作並看過 Console 沒有錯誤。
