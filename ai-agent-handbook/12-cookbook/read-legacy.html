食譜：讀懂舊的 MVC 專案

接手陌生專案的前兩天，怎麼用 agent 快速建立地圖。

情境

你被指派維護一個沒人說得清楚的舊專案。目標不是一次全懂，而是先建立地圖：入口在哪、請求怎麼流、資料從哪來、哪裡最危險。

先認出專案類型

線索代表入口檔
Program.cs、.csproj（SDK 格式）ASP.NET CoreProgram.cs、appsettings.json
Global.asax、Web.config、packages.config.NET Framework 的 ASP.NET MVC 5Global.asax.cs、App_Start/RouteConfig.cs、Web.config

步驟

  1. 唯讀導覽（計畫模式）： 
    > 我剛接手這個專案。請先判斷它是 ASP.NET Core 還是 .NET Framework MVC，
> 再帶我導覽：
> 1. 專案與資料夾結構各管什麼
> 2. 路由設定在哪、有哪些主要 Controller
> 3. 資料存取是怎麼做的（EF？Dapper？預存程序？）
> 4. 驗證與授權怎麼做
> 5. 前端怎麼組成（Razor、Vue、jQuery？打包方式？）
> 6. 設定與機密放在哪
> 每點附檔案路徑，不要貼大段程式碼。先不要修改任何檔案。
  2. 追一條主要流程：挑最核心的一個功能（例如下單），請它從畫面按鈕到資料庫完整追一次。
  3. 找風險：「列出最可能出問題、最難改的地方（重複的程式、過大的類別、沒有測試的核心邏輯、寫死的設定）。」
  4. 存成筆記：docs/notes/architecture.md，你用自己的話修改。以後直接讀它，不必重新探索。
  5. 確認能建置與測試：先把「怎麼建置、怎麼跑測試、怎麼啟動」寫進 CLAUDE.md。

可以追問的問題

  • 「這個 Controller 的某個 Action 呼叫了誰？誰又呼叫它？」
  • 「這個資料表／欄位在哪些地方被讀寫？」（改資料庫前必問）
  • 「這段程式為什麼這樣寫？有沒有可能是為了某個歷史原因？看得出來嗎？」（讓它區分「看得出」與「猜測」）

.NET Framework 專案的特別提醒

  • 建置與測試指令可能是 MSBuild 與 vstest，而不是 dotnet；請寫進 CLAUDE.md，並先在你的機器上確認能執行。
  • 設定在 Web.config，不同環境靠轉換檔（transform）；請 agent 說明不要擅自修改。
  • 套件管理可能是 packages.config；升級套件風險高，先評估再動。

檢查清單

  • 我有一份自己的架構筆記，且已驗證過至少三處。
  • 我知道怎麼建置、測試、啟動。
  • 我知道三個最危險、最需要小心的地方。
  • agent 說「看起來是…」的地方，我標示為待確認。

省 Token 技巧

  • 導覽用 subagent 做，只回報摘要與路徑。
  • 存成筆記，之後只讀筆記。
  • 追流程時指定起點與終點，不要「讀整個專案」。
