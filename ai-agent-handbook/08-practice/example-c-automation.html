範例 C：把每週手動流程改成自動化

以「每週客服週報」為例：從手動整理，到 skill，到排程，逐步放權。

這是示意情境。對話、檔名、數字都是為了說明流程而設計的範例，不是真實專案的執行結果；請把它當成可改造的腳本，換成你自己的專案與資料。

情境

每週五下午，你要花約一小時整理客服週報：從 Trello 找本週完成的卡片、對照行事曆的重要會議、彙整成固定格式。每週重複、格式固定、資料分散，是很好的自動化對象。

四個階段，逐步放權

階段做法放權程度
1. 寫下手動流程列出每一步的輸入與輸出，標出哪步是確定性、哪步需判斷無
2. 做成 skill，手動觸發一句話「產生本週週報」，全程唯讀，輸出草稿只讀
3. 排程自動產生草稿週五 16:00 自動執行 headless，存成檔案並通知你只讀 + 產生檔案
4. 低風險寫入經核准後，把週報貼到共用頁面或 Trello 卡片（先提案再核准）寫入需核准

步驟一：流程分類

步驟類型載體
取得本週完成的卡片確定性MCP 查詢（限定看板、清單、本週）
取得本週重要會議確定性行事曆 MCP（限定標籤或關鍵字）
分類成果、撰寫摘要需判斷agent（skill 內的格式與規則）
對照上週「下週計畫」需判斷agent 讀上週週報該段落
修改、補充、確認需決策你
發布對外可見你核准後才執行

步驟二：skill 範例

---
name: weekly-support-report
description: 產生客服週報草稿。當使用者要求週報、本週成果彙整時使用。
---
# 流程（全程唯讀）
1. 讀取 Trello「客服」看板本週移到「完成」的卡片：標題、負責人、連結。
2. 讀取本週行事曆中標籤為「重要」的會議：日期、標題。
3. 讀取 reports/ 中最近一份週報的「下週計畫」段落，逐項標示本週達成／未達成。
   原因未知時寫「待補」，不要推測。
4. 依 templates/weekly-report.md 格式輸出，全文不超過 60 行。
5. 輸出到 reports/週報-YYYY-MM-DD.md，不發布到其他地方。
不得編造沒有資料來源的內容。

步驟三：排程

# 每週五 16:00 執行（Windows 工作排程器示意）
claude -p "依 weekly-support-report skill 產生本週週報草稿" --max-turns 10
# 完成後以桌面通知提醒你審閱

排程細節見 06 排程；整合設計見 06 協作工具與食譜。

步驟四：寫入的安全流程

  1. agent 產生「預計發布的內容與目的地」，不執行。
  2. 你審閱、修改、核准。
  3. 執行發布，記錄目標位置，方便還原。

你做的決定

  • 哪些內容可以對外發布。
  • 「待補」的原因由誰補。
  • 何時從手動觸發升級到排程，何時開放寫入。

可能出錯的地方

坑對策
agent 為了版面完整而編造內容規定「沒資料寫待補」，抽查來源連結
查詢範圍太大，成本高、雜訊多限定看板、清單、時間範圍
外部服務授權過期，排程默默失敗失敗時通知；每次執行寫紀錄
你習慣直接用，不再讀每月抽查一次來源，確認內容真實

檢查清單

  • skill 全程唯讀，且輸出有格式與長度限制。
  • 連續數週手動觸發的輸出品質穩定，才進入排程。
  • 排程有失敗通知與執行紀錄。
  • 寫入動作一律先提案、再核准。
  • 手動做法仍有文件，隨時可以接手。

省 Token 技巧

  • 查詢限定看板、清單、本週，只取標題、負責人、連結。
  • 只讀上週週報的「下週計畫」段落，不讀全文。
  • 格式放範本檔，用 skill 按需載入。
  • 每週一次的頻率已足夠，不需要更常跑。
  • 例行摘要可用較小模型。
