模式與常用指令

掌握幾個開關，就能在「放手」與「掌控」之間切換。

權限模式（Shift+Tab 可循環切換）

模式行為何時用
預設每次編輯、執行指令都詢問剛開始、陌生專案
自動接受編輯檔案編輯免詢問，指令仍詢問已有 git、任務範圍清楚
計畫模式只讀不改，先提出計畫等你核准大任務、需求不確定、想先看方向
以命令列啟動時，可用 --permission-mode 指定模式。本機版本（Claude Code 2.1.322）實際列出的選項為 plan、acceptEdits、auto、manual、dontAsk、bypassPermissions；各模式的確切行為請以官方文件為準。

常用斜線指令

指令用途
/init掃描專案，產生初版 CLAUDE.md
/clear清空對話，開始新任務（最常用的省情境手段）
/compact摘要壓縮目前對話，保留重點、釋出空間
/resume回到之前的對話
/rewind 或連按兩次 Esc把對話與（程式碼）狀態退回先前某一步
/memory檢視、編輯載入的 CLAUDE.md
/permissions管理免詢問的指令白名單
/agents、/mcp、/plugin、/hooks管理 subagent、MCP、外掛、hooks（見 03、06）
/help列出目前版本全部指令

輸入技巧

同樣的需求，用對輸入方式，agent 拿到的資訊更準、你花的力氣更少。以下每項都附可直接照抄的範例。

1. @ 引用檔案與資料夾

輸入 @ 後接路徑，Tab 可自動補全。被引用的檔案內容會直接放進情境，agent 不必自己搜尋，也不會找錯檔。引用資料夾則給它該資料夾的檔案清單。

> 請看 @src/Orders/OrderService.cs，說明 Cancel 方法在什麼條件下會失敗

> 新增 ExportService，寫法請參考 @src/Reports/ReportService.cs 的結構與命名

> 比較 @docs/specs/order-filter.md 和 @src/Orders/OrderQuery.cs，
> 列出規格有寫但程式沒做的項目

> @src/Orders/ 這個資料夾各檔案分別負責什麼？

何時用：你已經知道檔案在哪。何時不用：還不知道在哪時，直接描述問題讓它自己搜尋，避免塞入無關檔案浪費情境。

2. ! 直接執行 shell 指令

在提示列開頭輸入 ! 切換成 shell 模式，指令會立刻執行，且輸出會進入對話情境，agent 接著就能根據結果行動。省掉「請你幫我跑…」的來回，也不消耗模型推理。

> !git status
> !dotnet test --filter OrderTests
（輸出出現後再接著說：）
> 上面第 2 個測試失敗，請找出原因並修正

> !git log --oneline -5
> 依上面最近 5 個 commit，幫我寫本週變更摘要

適合：跑測試、看 git 狀態、查環境版本、貼上你已知的錯誤輸出。注意：它以你的身分執行，輸入前確認指令安全。

3. 貼圖片：截圖、設計稿、錯誤畫面

圖片可以貼上（常見為 Ctrl+V，部分終端機或系統快捷鍵不同）、拖曳進終端機，或直接給路徑。前端排版、UI 對照設計稿、無法複製文字的錯誤視窗，圖片通常比文字描述準確很多。

> （貼上畫面截圖）
> 這是目前的訂單列表。表頭欄位沒有對齊，請找出對應的 CSS 並修正

> （貼上設計稿）+ （貼上目前畫面）
> 左邊是設計稿，右邊是現況，列出所有差異，再逐項修正

> 請看 C:/temp/error-dialog.png，這個錯誤是哪個流程觸發的？

技巧：一次貼多張時，在文字中標明各張是什麼（「第一張是設計稿」）。

4. 多行輸入

需求描述常常很長。Enter 預設是送出，換行要用其他方式：

方式說明
\ 加 Enter行尾輸入反斜線再按 Enter，通用於各終端機
Shift+Enter部分終端機可直接用；若無效，執行 /terminal-setup 設定
貼上多行文字直接貼，整段會視為同一則訊息
先寫成檔案再引用很長的需求寫在 task.md，再說「依 @task.md 執行」，還能版本控制

5. 中斷與退回

操作效果情境
Esc中斷目前動作，保留對話看到它方向走偏，立刻喊停並補一句「改用 X」
Esc 連按兩次開啟退回選單，回到先前某則訊息整段做錯，想回到那一步重新下指令
Ctrl+C取消目前輸入或中止執行；連按兩次離開輸入到一半想清掉
↑ / ↓叫出先前輸入過的指令重複下類似的指令
（agent 正要大改 Controller）
按 Esc
> 先停。這次只改 Service 層，不要動 Controller 的簽章。繼續

6. 斜線指令與模式切換

  • 輸入 / 會列出可用指令，打幾個字母可過濾；你自訂的指令與 skill 也會出現在這裡。
  • Shift+Tab 循環切換權限模式，不必離開輸入框。

7. 組合範例：一次用上多種技巧

（Shift+Tab 切到計畫模式）
> !git diff --stat
> 這是我目前未提交的變更。請對照 @docs/specs/order-filter.md，
> 檢查有沒有偏離規格；另外參考這張畫面（貼圖）確認 UI 欄位是否齊全。
> 先給我問題清單，不要改任何檔案

這一則訊息同時：切換成唯讀的計畫模式、帶入實際變更、引用規格檔、附上畫面、並明確限制「只列清單」。agent 一次拿到完整的對照材料。

常見錯誤

做法問題改善
一次 @ 引用十幾個檔案情境被塞滿，重點被稀釋只引用必要的 2～3 個，其餘讓它自己搜尋
貼整份 log 文字大量雜訊用 ! 跑指令並篩選，或只貼錯誤附近的段落
看它走偏仍等它做完浪費時間，還得退回發現就按 Esc 中斷修正方向
很長的需求每次重打容易漏、無法重用寫成 md 檔用 @ 引用
指令名稱、快捷鍵與檔案位置會隨版本調整，以官方文件與你機器上 /help 的顯示為準。

省 Token 技巧

操作省在哪範例
/clear丟掉舊歷史，後續每輪都更便宜修完 bug 要做新功能時先 /clear
/compact 指示壓縮對話並指定保留重點/compact 保留目前計畫與已修改的檔案清單，其他可丟
/context找出誰在吃情境發現某 MCP 佔了大量空間，就停用它
/model簡單任務改用較小較省的模型改名、格式整理用小模型；設計與疑難除錯用大模型
計畫模式先對齊方向，避免寫完整包再重做Shift+Tab 切到計畫模式再下大任務
@檔案直達目標，免去 agent 反覆搜尋@src/Orders/OrderService.cs
!指令你自己跑指令，不經模型推理!git status
Esc 中斷發現走偏立即停止，少付一整段錯誤輸出見上方「中斷與退回」

壓縮的時機

在任務的「自然停頓點」壓縮（一個階段完成、準備進入下一個）比在做到一半時壓縮好，因為此時最容易說清楚「哪些要留」。
