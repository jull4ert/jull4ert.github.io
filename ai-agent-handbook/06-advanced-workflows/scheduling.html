排程與定時工作

讓 agent 在固定時間或事件發生時自己跑，你只看結果。

三種做法

做法特色適合
對話內的循環／輪詢在目前對話中，每隔一段時間重複某個提示（部分版本提供 /loop 類功能）盯著部署、CI、待辦，短時間內的輪詢
作業系統排程 + headlessWindows 工作排程器、cron 等定時執行 claude -p每日晨報、每週彙整，在你的電腦上跑
雲端排程由服務端依排程執行（部分版本提供排程代理／routines 之類功能）不依賴你的電腦開機的長期工作

是否提供、名稱為何，因版本與方案而異，請查 /help 與官方文件。

範例：Windows 每天早上產生晨報

# scripts/morning-brief.ps1
$out = "D:/notes/brief/$(Get-Date -Format yyyy-MM-dd).md"
claude -p "依 morning-brief skill 產生今日晨報" --output-format text --max-turns 8 | Out-File $out -Encoding utf8

# 註冊每天 08:30 執行
schtasks /Create /SC DAILY /ST 08:30 /TN "MorningBrief" /TR "powershell -File D:/scripts/morning-brief.ps1"

Linux 或 macOS 可用 cron：30 8 * * 1-5 /path/morning-brief.sh（週一至週五 08:30）。

適合排程的工作

工作頻率輸出
晨報：今日行程 + 待辦 + 需要回覆的信每個工作日早上一份 md 或訊息
週報彙整：完成的卡片、commit、會議每週五週報草稿
依賴與弱點巡檢每週有問題才通知
過期待辦檢查每日清單，列出逾期卡片
文件健康檢查每月過時或矛盾的文件清單

排程工作的設計守則

  • 只唯讀、只產生報告：無人在場時，不要讓它自行修改或發送。
  • 輸出寫成檔案或通知：可追查、可回顧。
  • 沒事就安靜：「沒有異常就不要通知」，避免你習慣忽略。
  • 設上限：輪數、逾時、頻率，避免失控消耗。
  • 記錄每次執行：時間、結果、失敗原因。
  • 冪等：同一天重跑不會產生重複結果。

省 Token 技巧

  • 頻率配合需求：每小時跑的事，是否真的需要每小時？多數每日即可。
  • 先用腳本判斷有沒有事：沒有變化就不呼叫 agent（例如先檢查有沒有新 commit）。
  • 輪詢用大間隔：等待不需要時時檢查。
  • 限制資料範圍：「過去 24 小時、與我有關」。
  • 使用較小模型：例行摘要不需要最大模型。
  • 沒異常輸出一行即可。
旗標、指令與設定欄位會隨版本調整，請以官方文件與 claude --help 的實際輸出為準；範例腳本請先在安全的環境小規模測試。
