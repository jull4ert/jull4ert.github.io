Headless 與 CI 整合

不開互動畫面，讓 agent 在腳本與 CI 裡自動執行。

Headless 模式

用 -p（print）旗標，agent 接收一次提示、執行、輸出結果後結束，可直接放進腳本與 CI。

claude -p "列出 src/Orders 中所有沒有測試覆蓋的 public 方法"

# 搭配管線
git diff main | claude -p "用繁體中文摘要這份變更，列出風險"

# 指定輸出格式（text / json / stream-json）與限制
claude -p "分析 build.log 的失敗原因" --output-format json --max-turns 5
常用旗標用途
-p非互動，執行後輸出並結束
--output-formattext、json、stream-json，方便程式解析
--max-turns限制最多幾輪，避免失控（實測可用；--help 未列出）
--max-budget-usd用量金額上限，只搭配 -p
--permission-mode可選 plan、acceptEdits、auto、manual、dontAsk、bypassPermissions；無人值守建議用限縮的模式並事先限定工具
--bare精簡模式：略過 hooks、外掛同步、CLAUDE.md 自動探索，需自行以參數提供脈絡
--allowedTools只允許指定工具，非互動環境必須事先決定權限
--resume / --continue接續先前的對話
非互動環境沒有人可以按核准，所以權限要事先限縮到最小：只開需要的工具、在隔離的環境（容器、臨時目錄、沙箱）執行，不要給正式環境的憑證。

在 GitHub Actions 的應用

用途觸發
PR 自動審查PR 開啟或更新時，讀 diff，留下審查意見
回應留言在 PR 或 Issue 留言提及 agent，請它修正或回答
修復 CI 失敗測試失敗時分析 log、提出修正
Issue 分類新 Issue 進來，自動貼標籤、補問缺少的資訊
# .github/workflows/review.yml（示意，實際請依官方文件）
name: claude-review
on:
  pull_request:
    types: [opened, synchronize]
jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: |
            審查這個 PR 的變更。標準見 CLAUDE.md；規格見 docs/specs/。
            只回報有證據的問題，依嚴重度排序，沒有高嚴重度請明說。

官方也提供在 Claude Code 內用 /install-github-app 之類的方式快速設定，細節以官方文件為準。

CI 整合的安全原則

  • 金鑰放在 CI 的 secrets，不寫進程式碼或 workflow 檔。
  • 最小權限：permissions 只給需要的（例如只讀內容、可寫 PR 留言）。
  • 不要對來自 fork 的不明 PR 開放高權限：PR 內容可能夾帶針對 agent 的惡意指示。
  • agent 的輸出視為建議：不自動合併、不自動部署。
  • 設定上限：--max-turns、逾時、每日用量，避免成本失控。

省 Token 技巧

  • 只傳 diff，不傳整個專案：git diff 當輸入。
  • 只在需要時觸發：用路徑條件，文件變更不必跑程式審查；草稿 PR 先不審。
  • 限制輪數與輸出：--max-turns、「最多 5 項」。
  • 先用便宜的檢查擋掉：lint、建置失敗就不必叫 agent 審。
  • 快取審查結果：同一個 commit 不重複審。
旗標、指令與設定欄位會隨版本調整，請以官方文件與 claude --help 的實際輸出為準；範例腳本請先在安全的環境小規模測試。
