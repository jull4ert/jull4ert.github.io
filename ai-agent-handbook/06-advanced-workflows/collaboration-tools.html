整合行事曆、Trello 與協作工具

用 MCP 讓 agent 讀寫你每天用的工具，並用安全的流程避免誤操作。

整合的基本架構

你 ──► agent ──► MCP 伺服器 ──► 行事曆 / Trello / Slack / Gmail / Notion │ ├─ skill：固定流程與輸出格式（見 03） └─ 人工關卡：寫入前由你核准

MCP 的連線與安全設定見 03 MCP。這一頁專注在「怎麼設計流程」。

各工具能做什麼

工具讀取寫入（需核准）
行事曆今日／本週行程、空檔、衝突建立事件、邀請與會者、調整時間
Trello看板、清單、卡片、期限、成員建立卡片、移動清單、指派、加註解
Slack頻道與討論串摘要、未讀發訊息、回覆
Gmail搜尋、摘要、待回信件起草回覆（建議只存成草稿）
Notion／文件搜尋、讀取頁面更新紀錄、建立頁面
行事曆與 Trello 等服務是否有可信的 MCP 伺服器、各自提供哪些工具，請實際查證來源（官方或你信任的作者）。沒有現成伺服器時，可用該服務的 API 搭配腳本，再包成 skill，由 agent 呼叫腳本。

安全的寫入流程：五步

步驟內容
1. 讀取只讀，蒐集現況（既有卡片、行事曆空檔）
2. 提案產生「預計執行的動作清單」，不執行
3. 核准你逐項或整批確認，可修改
4. 執行只執行核准過的項目，並記錄建立的 ID
5. 回報列出實際做了什麼與連結，方便回滾

避免誤操作的設計

  • 去重：建卡前先搜尋既有卡片，已存在就不重複建立。
  • 標記來源：agent 建立的卡片加標籤或註解（例如「由 agent 建立」），之後好查、好清。
  • 記錄 ID：每次寫入把建立的卡片或事件 ID 存檔，出錯可批次還原。
  • 不碰別人的東西：預設只改自己建立或指派給自己的項目。
  • 對外動作永遠人工確認：邀請外部與會者、發送訊息、寄信。
  • 先小範圍試跑：用測試看板或個人行事曆試過再正式使用。

常見的工作流程模式

模式說明
彙整跨工具蒐集資料，產出單一摘要（晨報、週報）
抽取從會議紀錄、信件抽出待辦，轉成卡片草稿
同步卡片期限 ↔ 行事曆提醒，讓重要期限有時間區塊
檢查找逾期、無負責人、卡住太久的卡片
排程建議依行事曆空檔，建議何時處理哪些待辦

省 Token 技巧

  • 查詢要有範圍：「本週、指派給我、尚未完成」，而不是整個看板。
  • 只取需要的欄位：標題、期限、狀態；卡片全文與附件留到需要時再讀。
  • 先腳本篩選，再給 agent：能用條件過濾的先過濾。
  • 摘要輸出：「每項一行」，不要全文複述。
  • 不用的 MCP 不要連線：工具定義本身就佔情境。
  • 中間結果存檔：蒐集一次、存成檔案，後續步驟讀檔，不重複查詢。
