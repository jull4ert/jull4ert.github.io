資料外洩

確認或疑似個資、機敏資料被未授權存取或取走。

通用流程見 應變流程。本頁是這個情境的補充重點。

徵兆

  • 資料出現在暗網、貼文或第三方通報
  • 資料庫或儲存桶異常大量讀取、匯出
  • 公開的儲存桶、備份檔或 API 可無認證取得資料
  • 員工誤寄、誤傳資料給外部

最先做

  1. 升級為 P1 並通知客戶窗口與法務
  2. 確認外洩資料的類型、筆數、時間範圍與可識別性
  3. 保存存取日誌與證據，記錄時間線

遏止

  • 封閉暴露點：設為私有、移除公開連結、停用被濫用的金鑰與權杖
  • 強制登出相關工作階段並重設受影響帳號密碼
  • 對外洩出去的憑證立即輪替

根除

  • 找出入口與根因，修補漏洞或錯誤設定
  • 確認資料是否被複製到其他位置，必要時要求第三方下架

復原

  • 提供受影響使用者的補救措施（改密碼、留意釣魚）
  • 加強監控並持續檢視一段時間

通報判斷

  • 依 通報規則 判斷是否需通知當事人與主管機關；時限從「知悉」起算
  • 我方儘速提供完整事實給客戶（客戶多為控管者），由客戶決定通報內容
  • 保存所有通報紀錄

常見錯誤

  • 在確認前就對外說「沒有外洩」
  • 延遲通知客戶，等調查完才說
  • 只修補而沒確認其他資料是否已被取走
