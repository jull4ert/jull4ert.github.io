HTTP 安全標頭與 Cookie

用回應標頭告訴瀏覽器啟用哪些防護，降低 XSS、點擊劫持等風險。

建議標頭

標頭作用範例
Content-Security-Policy限制可載入的腳本／資源來源，XSS 的重要第二道防線default-src 'self'; object-src 'none'; frame-ancestors 'none'
X-Content-Type-Options禁止瀏覽器猜測內容類型nosniff
Referrer-Policy控制 Referer 洩漏的資訊量strict-origin-when-cross-origin
Permissions-Policy關閉用不到的瀏覽器功能camera=(), microphone=(), geolocation=()
防嵌入（點擊劫持）禁止被他站 iframe 嵌入CSP 的 frame-ancestors（舊瀏覽器可加 X-Frame-Options: DENY）
Strict-Transport-Security強制 HTTPS見 TLS 設定
CSP 若直接上最嚴格設定，容易讓既有頁面壞掉。建議先以 Content-Security-Policy-Report-Only 觀察違規報告，修正後再正式啟用。

移除洩漏資訊的標頭

隱藏 Server、X-Powered-By、X-AspNet-Version 等版本資訊，避免攻擊者精準比對漏洞。這只是減少資訊暴露，不能取代修補。

Cookie 旗標

屬性作用
Secure只透過 HTTPS 傳送
HttpOnlyJavaScript 無法讀取，降低 XSS 竊取 Session
SameSiteLax 或 Strict 降低 CSRF；跨站需求才用 None（且需 Secure）
名稱前綴 __Host-強制 Secure、Path=/、不帶 Domain，防止子網域覆寫
有效期Session Cookie 設合理逾時，登出時伺服器端同步失效
Set-Cookie: __Host-session=...; Path=/; Secure; HttpOnly; SameSite=Lax

CORS

  • 不要在帶憑證的 API 使用 Access-Control-Allow-Origin: *。
  • 以白名單列出允許的來源，不要把請求的 Origin 原樣回填。
