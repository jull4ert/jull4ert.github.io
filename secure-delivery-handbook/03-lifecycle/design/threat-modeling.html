威脅建模

系統性地回答「會被怎麼攻擊」，而不是憑感覺列清單。

四個核心問題

  1. 我們在做什麼？（畫架構圖／資料流圖）
  2. 可能出什麼錯？（用 STRIDE 等方法找威脅）
  3. 我們要怎麼處理？（緩解、轉移、接受、避免）
  4. 做得夠好嗎？（驗證並回頭檢討）

STRIDE 分類

字母威脅破壞的性質常見緩解
S偽冒（Spoofing）身分驗證強認證、MFA、簽章
T竄改（Tampering）完整性輸入驗證、簽章、存取控制
R否認（Repudiation）不可否認性稽核日誌、時間戳
I資訊洩漏（Information disclosure）機密性加密、授權檢查、最小回傳欄位
D阻斷服務（Denial of service）可用性速率限制、資源配額、快取、DDoS 防護
E權限提升（Elevation of privilege）授權最小權限、伺服器端授權檢查

範例：登入功能

威脅類別緩解
攻擊者以字典檔暴力猜密碼S登入失敗次數限制、延遲、MFA、異常告警
Session 被竊取後冒用S／IHttpOnly／Secure Cookie、綁定風險訊號、登出即失效
以他人 ID 呼叫 API 取得資料（IDOR）I／E每次請求在伺服器端檢查資源擁有權
錯誤訊息洩漏帳號是否存在I登入與忘記密碼回應訊息一致
大量請求登入端點拖垮服務D速率限制、驗證碼、WAF

實務建議

  • 範圍小而頻繁：每個新功能或重大變更就做一次，不必一次完成全系統。
  • 輸出為可追蹤項目：每個威脅對應一個緩解措施與負責人。
  • 邀請開發、維運、資安一起，而非資安獨自完成。
