安全需求

把「要安全」寫成可驗證的需求，才能在驗收時逐項檢查。

好的安全需求

  • 可驗證：能用測試或檢查明確判定通過與否。
  • 具體：有數值或明確行為。
  • 可追溯：對應到風險或法規。

寫法對照

不好的寫法較好的寫法
系統要安全所有對外連線強制 HTTPS，僅啟用 TLS 1.2 以上
密碼要夠強密碼至少 12 字元，不得出現於常見洩漏密碼清單，以 Argon2id 或 bcrypt 雜湊儲存
要記錄操作所有登入、權限變更、資料匯出皆寫入稽核日誌，保存 N 個月，且一般管理者無法修改
防止越權每個資料存取 API 在伺服器端驗證呼叫者對該資源的權限，測試案例涵蓋橫向越權

需求來源

  • OWASP ASVS：分 L1／L2／L3 三個驗證等級，可作為需求清單的起點，並與風險分級對應。
  • 客戶合約與法規條文。
  • 威脅模型產出的緩解項目。
建議對應：風險 L2 取 ASVS L1 為底再補強；L3、L4 以 ASVS L2 以上為目標。此為經驗建議，並非 ASVS 本身規定。
