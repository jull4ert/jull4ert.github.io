安全編碼

針對網站前後端最常見弱點的正確寫法。

弱點與做法對照

弱點做法
SQL 注入一律使用參數化查詢或 ORM，不用字串串接組 SQL
XSS輸出時依情境編碼；使用框架預設的自動跳脫；避免 innerHTML；搭配 CSP
CSRFSameSite Cookie 加 CSRF token；變更狀態的操作不用 GET
越權（IDOR／存取控制失效）每次請求在伺服器端檢查呼叫者對資源的權限，不依賴前端隱藏按鈕或可預測 ID
認證缺陷使用成熟的身分驗證框架；密碼以 Argon2id／bcrypt 雜湊；限制失敗次數；啟用 MFA
敏感資料暴露只回傳必要欄位；機敏資料加密儲存；日誌不記密碼與 token
SSRF伺服器代為請求外部網址時採白名單，禁止指向內網與中繼資料位址
不安全的反序列化／檔案上傳限制型別與大小、檢查內容、儲存於網站目錄之外並重新命名
錯誤處理對使用者顯示通用訊息，詳細錯誤只寫入伺服器日誌
加密使用成熟函式庫，不自行發明演算法；金鑰不寫死在程式碼

範例：參數化查詢

// 不安全：字串串接
var sql = "SELECT * FROM Users WHERE Email = '" + email + "'";

// 安全：參數化（以 Dapper 為例）
var user = connection.QueryFirstOrDefault<User>(
    "SELECT * FROM Users WHERE Email = @email", new { email });
