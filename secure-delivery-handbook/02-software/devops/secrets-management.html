密鑰管理

密碼、API 金鑰、憑證與連線字串的安全取得與輪替。

原則

  • 密鑰不進版控、映像或前端；不同環境使用不同密鑰。
  • 集中管理、可稽核、可輪替；應用程式以身分（受管理身分／IAM 角色）取得，而不是再放一把「取密鑰的密鑰」。
  • 最小權限：每個服務只能讀自己需要的密鑰。
  • 定期輪替，人員異動或疑似外洩時立即輪替（見機敏資訊外洩）。

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。

適用本機開發與簡單部署；.env 必須列入 .gitignore，正式環境不建議以檔案長期存放。

# .gitignore
.env

# .NET 開發期可用 user-secrets（存在使用者目錄，不進專案）
dotnet user-secrets set "Db:Password" "<value>" 
vault kv put secret/myapp/db password="<value>"
vault kv get -field=password secret/myapp/db

正式環境建議以 AppRole／Kubernetes 驗證等方式取得短效 token，並使用動態密鑰（dynamic secrets）。

az keyvault secret set --vault-name <vault> --name DbPassword --value "<value>"
az keyvault secret show --vault-name <vault> --name DbPassword --query value -o tsv

// .NET：以受管理身分讀取
builder.Configuration.AddAzureKeyVault(
    new Uri("https://<vault>.vault.azure.net/"), new DefaultAzureCredential());
aws secretsmanager create-secret --name myapp/db --secret-string '{"password":"<value>"}'
aws secretsmanager get-secret-value --secret-id myapp/db --query SecretString --output text

應用程式以 IAM 角色存取，並可啟用自動輪替。
