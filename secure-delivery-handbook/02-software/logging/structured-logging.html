結構化日誌

用參數化訊息記錄事件，避免字串拼接造成日誌注入與格式混亂。

原則

  • 使用訊息範本＋參數，不要用字串插值拼訊息。
  • 每筆含：時間、等級、事件名稱、使用者／來源 IP、關聯 ID（Trace／Request ID）。
  • 對可能含機敏資料的欄位做遮罩或排除。
  • 使用者輸入若直接進入日誌，需處理換行字元（CRLF）以防偽造日誌行。

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。
// Serilog：具名屬性，保留結構
Log.Warning("Login failed for {UserId} from {Ip}", userId, ip);
// 避免：Log.Warning($"Login failed for {userId}")
// pino：物件在前、訊息在後
logger.warn({ userId, ip, event: 'login_failed' }, 'login failed');
// SLF4J：參數化訊息（避免字串串接）
log.warn("login failed user={} ip={}", userId, ip);
logger.warning("login failed user=%s ip=%s", user_id, ip)
# 或使用 structlog 輸出 JSON
// Monolog
$log->warning('login failed', ['user' => $userId, 'ip' => $ip]);
