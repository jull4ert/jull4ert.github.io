OWASP API Security Top 10 對照

針對 API 的十大風險與對應的防護方式。

此為 OWASP API Security Top 10 2023 版的類別；若有新版請以官網為準。
編號風險防護重點
API1物件層級授權失效（BOLA）每次存取資源檢查擁有權，見 授權
API2驗證失效成熟的驗證機制、限制嘗試、MFA、token 驗證完整
API3物件屬性層級授權失效回應只含呼叫者可見欄位；更新時用 DTO 白名單，防大量賦值（mass assignment）
API4無限制的資源消耗速率限制、分頁上限、請求大小與逾時，見 速率限制
API5功能層級授權失效（BFLA）管理類端點檢查角色，預設拒絕
API6敏感商業流程無限制存取對搶購、註冊、領券等流程加防自動化機制
API7伺服器端請求偽造（SSRF）對外請求目的地白名單，禁止內網與中繼資料位址
API8安全設定錯誤移除除錯、關閉預設設定、一致的 TLS／標頭／CORS
API9資產管理不當API 清單、版本管理、下線舊版與測試端點
API10不安全地使用其他 API第三方回應當作不可信輸入驗證、設逾時與重試上限

防止大量賦值（Mass Assignment）

  • 輸入使用專用 DTO／請求模型，只包含允許修改的欄位。
  • 不要把請求本文直接綁定到資料庫實體（避免使用者改到 isAdmin、price 等欄位）。
