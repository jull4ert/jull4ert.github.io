速率限制

限制單一來源的請求量，防止暴力破解、爬取與資源耗盡。

原則

  • 分層：邊界（CDN／WAF／API 閘道）擋大流量，應用層針對登入、簡訊、搜尋等敏感端點細部限制。
  • 限制維度：IP、帳號、API 金鑰；登入端點同時限制帳號與來源。
  • 超過限制回 429 Too Many Requests 並附 Retry-After。
  • 在反向代理後面時，取得真實來源 IP（正確設定受信任的代理），否則會誤把所有人視為同一個來源。
  • 多執行個體部署時，計數需使用共享儲存（如 Redis）。

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。
builder.Services.AddRateLimiter(o => {
    o.RejectionStatusCode = 429;
    o.AddFixedWindowLimiter("login", c => {
        c.PermitLimit = 5; c.Window = TimeSpan.FromMinutes(1);
    });
});
app.UseRateLimiter();
// 端點：[EnableRateLimiting("login")] 或 .RequireRateLimiting("login")
import rateLimit from 'express-rate-limit';
app.use('/login', rateLimit({ windowMs: 60_000, limit: 5 }));
// 舊版本的選項名稱為 max；多執行個體請搭配共享 store

Spring 沒有內建的通用速率限制：可使用 API 閘道（如 Spring Cloud Gateway 的 RequestRateLimiter 搭配 Redis）或函式庫（如 Bucket4j）。

# Django：django-ratelimit
from django_ratelimit.decorators import ratelimit
@ratelimit(key='ip', rate='5/m', block=True)
def login(request): ...
// Laravel
Route::post('/login', [AuthController::class, 'login'])->middleware('throttle:5,1');
