XSS 與內容安全政策（CSP）

防止攻擊者把腳本塞進你的頁面並在使用者瀏覽器執行。

原則

  • 輸出時依情境編碼（HTML 內容、屬性、URL、JavaScript）；不要只靠輸入過濾。
  • 優先使用框架預設的自動跳脫，避開「輸出原始 HTML」的 API。
  • 必須輸出使用者提供的 HTML 時，先以成熟的清理函式庫過濾（如 DOMPurify），並限制允許的標籤。
  • href、src 等 URL 欄位只允許 http(s)，擋掉 javascript:。
  • 以 CSP 當第二道防線：即使有漏洞也限制腳本能做什麼。

CSP 範例

Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-{每次請求隨機值}';
  object-src 'none';
  base-uri 'self';
  frame-ancestors 'none'
  • 避免 'unsafe-inline' 與 'unsafe-eval'；內嵌腳本用 nonce 或 hash。
  • 先用 Content-Security-Policy-Report-Only 蒐集違規再正式啟用。
  • 進階：Trusted Types（require-trusted-types-for 'script'）限制危險 DOM 寫入。

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。
// 危險：會解析 HTML
el.innerHTML = userInput;
// 安全：當成純文字
el.textContent = userInput;

// 必須輸出 HTML 時先清理
import DOMPurify from 'dompurify';
el.innerHTML = DOMPurify.sanitize(userHtml);

模板的 {{ }} 會自動跳脫；v-html 不會。

<p>{{ comment }}</p>                 <!-- 安全 -->
<p v-html="comment"></p>              <!-- 危險：不要直接放使用者內容 -->
<p v-html="sanitize(comment)"></p>    <!-- 需要時先清理 -->

JSX 內的 { } 會自動跳脫；dangerouslySetInnerHTML 不會。

<div>{comment}</div>                                   // 安全
<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(html) }} />  // 需先清理
<a href={isHttpUrl(url) ? url : '#'}>連結</a>          // 驗證協定，擋 javascript:

插值與 [innerHTML] 預設會被 Angular 清理；繞過清理的 bypassSecurityTrust* 系列 API 要避免。

<p>{{ comment }}</p>                  <!-- 跳脫 -->
<div [innerHTML]="html"></div>        <!-- 內建清理 -->
// 避免：this.sanitizer.bypassSecurityTrustHtml(html)
