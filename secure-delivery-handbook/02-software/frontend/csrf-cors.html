CSRF 與 CORS

避免使用者在不知情下被別的網站觸發操作，並正確設定跨來源存取。

原則

  • 使用 Cookie 驗證的網站才有 CSRF 風險；純以 Authorization 標頭帶 token 的 API 通常不受影響。
  • 多層防護：SameSite=Lax/Strict Cookie ＋ CSRF token（或自訂標頭）＋ 變更狀態的操作不用 GET。
  • CORS 只決定「瀏覽器是否讓別的來源讀回應」，不是授權機制，也擋不住 CSRF。

CORS 設定

做法風險
Access-Control-Allow-Origin: * 搭配憑證瀏覽器不允許，且代表設計有問題
把請求的 Origin 原樣回填等同允許所有來源，風險高
白名單明列允許的來源建議做法
預檢（OPTIONS）快取過久設定變更後不易生效

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。

前端：送出請求時帶 token

fetch('/api/orders', {
  method: 'POST',
  credentials: 'same-origin',
  headers: { 'Content-Type': 'application/json', 'X-CSRF-Token': csrfToken },
  body: JSON.stringify(data)
});

使用 axios 時，同源請求預設會讀取名為 XSRF-TOKEN 的 Cookie，並放入 X-XSRF-TOKEN 標頭；後端需配合發放與驗證。

同 Vue：若使用 axios 即適用上述預設行為；使用 fetch 時需自行讀取並加入標頭。

HttpClient 內建此機制：從 XSRF-TOKEN Cookie 讀值，對同源的變更請求加上 X-XSRF-TOKEN 標頭。

provideHttpClient(withXsrfConfiguration({
  cookieName: 'XSRF-TOKEN', headerName: 'X-XSRF-TOKEN'
}))

後端：驗證 token

builder.Services.AddControllersWithViews(o =>
    o.Filters.Add(new AutoValidateAntiforgeryTokenAttribute()));

csurf 已停止維護，請改用仍在維護的套件（如 csrf-csrf），或採 SameSite Cookie ＋ 自訂標頭的作法，並確認套件的最新狀態。

Spring Security 對一般 Servlet 應用預設啟用 CSRF 防護；給 SPA 讀取 token 時：

http.csrf(csrf -> csrf
    .csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse()));

Django 預設啟用 CsrfViewMiddleware；表單使用 {% csrf_token %}，AJAX 於標頭帶 X-CSRFToken。

Laravel 預設啟用 CSRF 中介層；表單使用 @csrf，AJAX 於標頭帶 X-CSRF-TOKEN。
