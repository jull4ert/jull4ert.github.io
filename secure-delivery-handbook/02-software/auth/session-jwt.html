Session 與 JWT

登入後如何維持身分：伺服器端 Session 與無狀態 token 的取捨。

比較

伺服器端 Session（Cookie）JWT（Bearer token）
撤銷容易：伺服器刪除即可困難：需短效期＋刷新輪替或黑名單
擴充性需共享儲存無狀態，易水平擴充
主要風險CSRF（用 SameSite＋token）存放位置：放 localStorage 會被 XSS 竊取
適合傳統網站、同網域跨服務 API、行動 App

原則

  • 網站優先使用 HttpOnly、Secure、SameSite 的 Session Cookie。
  • JWT 驗證務必檢查：簽章演算法白名單、iss、aud、exp；不接受 alg: none。
  • Access token 短效（分鐘級）；Refresh token 輪替並可撤銷，儲存於 HttpOnly Cookie 或安全儲存區。
  • 登出與密碼變更時使 Session／refresh token 失效。
  • JWT 內不放敏感資料（內容只是 Base64，不是加密）。

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
  .AddJwtBearer(o => {
    o.Authority = "https://login.example.com/";   // 由 OIDC metadata 取得簽章金鑰
    o.TokenValidationParameters = new TokenValidationParameters {
      ValidateIssuer = true,
      ValidateAudience = true, ValidAudience = "my-api",
      ValidateLifetime = true,
      ValidateIssuerSigningKey = true,
      ValidAlgorithms = new[] { SecurityAlgorithms.RsaSha256 }
    };
  });
import jwt from 'jsonwebtoken';
const payload = jwt.verify(token, publicKey, {
  algorithms: ['RS256'],            // 明確限制演算法
  issuer: 'https://login.example.com/',
  audience: 'my-api',
});

Spring Security 作為 Resource Server：

# application.properties
spring.security.oauth2.resourceserver.jwt.issuer-uri=https://login.example.com/

// SecurityFilterChain
http.oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults()));
import jwt  # PyJWT
payload = jwt.decode(
    token, public_key,
    algorithms=["RS256"],
    audience="my-api",
    issuer="https://login.example.com/",
)

Laravel 常見做法是使用內建的 Session Cookie（網站）或 Sanctum／Passport（API token）。若自行驗證 JWT，使用成熟函式庫（如 firebase/php-jwt），並明確指定允許的演算法與驗證 iss／aud／exp。
