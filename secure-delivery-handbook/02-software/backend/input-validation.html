輸入驗證與檔案上傳

在邊界處以結構化方式驗證每一筆輸入，並嚴格處理上傳檔案。

原則

  • 白名單優於黑名單：定義允許的型別、長度、格式、範圍。
  • 在信任邊界（API 入口）驗證，並在伺服器端執行；失敗就拒絕，不要試圖修正。
  • 限制請求大小、欄位數量、巢狀深度，防止資源耗盡。
  • 驗證不是跳脫：驗證後輸出仍需依情境編碼。

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。
public record CreateUserRequest(
    [property: Required, StringLength(50, MinimumLength = 2)] string Name,
    [property: Required, EmailAddress] string Email);
// 搭配 [ApiController]，驗證失敗自動回 400
import { z } from 'zod';
const CreateUser = z.object({
  name: z.string().min(2).max(50),
  email: z.string().email(),
});
const data = CreateUser.parse(req.body); // 不合法會丟出例外
public record CreateUserRequest(
    @NotBlank @Size(min = 2, max = 50) String name,
    @NotBlank @Email String email) {}

@PostMapping("/users")
ResponseEntity<?> create(@Valid @RequestBody CreateUserRequest req) { ... }
from pydantic import BaseModel, EmailStr, Field
class CreateUser(BaseModel):
    name: str = Field(min_length=2, max_length=50)
    email: EmailStr   # 需安裝 email-validator
$data = $request->validate([
    'name'  => 'required|string|min:2|max:50',
    'email' => 'required|email',
]);
