注入防護

SQL、OS 命令、LDAP、NoSQL 等注入的共同根因：把資料當成指令。

原則

  • 資料與指令分離：用參數化查詢或預備陳述式，不要字串串接。
  • 無法參數化的部分（欄位名、排序方向、表名）用白名單對照。
  • 避免呼叫 shell；必要時用參數陣列的 API，不經過 shell 解析。
  • 資料庫帳號權限最小化，降低注入成功後的損害（見資料庫）。

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。
// Dapper
var user = conn.QueryFirstOrDefault<User>(
    "SELECT * FROM Users WHERE Email = @email", new { email });

// EF Core：插值字串會被轉為參數
var users = db.Users.FromSql($"SELECT * FROM Users WHERE Email = {email}").ToList();
// 危險：FromSqlRaw 搭配字串串接
// pg
await pool.query('SELECT * FROM users WHERE email = $1', [email]);
// mysql2
await conn.execute('SELECT * FROM users WHERE email = ?', [email]);
PreparedStatement ps = conn.prepareStatement(
    "SELECT * FROM users WHERE email = ?");
ps.setString(1, email);

// Spring Data JPA
@Query("select u from User u where u.email = :email")
User findByEmail(@Param("email") String email);
# psycopg
cur.execute("SELECT * FROM users WHERE email = %s", (email,))
# sqlite3
cur.execute("SELECT * FROM users WHERE email = ?", (email,))
$stmt = $pdo->prepare('SELECT * FROM users WHERE email = :email');
$stmt->execute(['email' => $email]);
// 建議連線時設定 PDO::ATTR_EMULATE_PREPARES => false

其他注入

類型防護
OS 命令不用 shell；使用參數陣列（如 .NET ProcessStartInfo.ArgumentList、Node execFile、Python subprocess.run([...]) 且不開 shell=True）
NoSQL（如 MongoDB）驗證輸入型別，避免把使用者物件直接當查詢條件（防止 $ne 等運算子注入）
LDAP對特殊字元做 LDAP 專用跳脫
模板注入不要把使用者輸入當成模板本身編譯
