權限與加密

以各資料庫的指令落實最小權限與加密連線。

原則

  • 區分帳號：應用程式帳號（DML）、遷移帳號（DDL，僅於部署時使用）、唯讀報表帳號。
  • 只授權必要的物件與操作；避免授予整個資料庫的高權限角色。
  • 連線強制 TLS 並驗證伺服器憑證，連線字串存放於密鑰管理（見 DevOps）。
  • 需要列級或租戶隔離時使用資料庫原生功能（如 Row-Level Security）。

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。
CREATE LOGIN app_login WITH PASSWORD = '<由密鑰管理產生>';
CREATE USER app_user FOR LOGIN app_login;
GRANT SELECT, INSERT, UPDATE ON dbo.Orders TO app_user;   -- 不授 db_owner

-- 連線字串：Encrypt=True;TrustServerCertificate=False
-- 靜態加密：TDE；欄位層：Always Encrypted；列級：Row-Level Security
CREATE ROLE app LOGIN PASSWORD '<由密鑰管理產生>';
REVOKE ALL ON SCHEMA public FROM PUBLIC;
GRANT USAGE ON SCHEMA public TO app;
GRANT SELECT, INSERT, UPDATE ON orders TO app;

-- 連線：sslmode=verify-full
-- 列級隔離：ALTER TABLE orders ENABLE ROW LEVEL SECURITY; + CREATE POLICY ...
CREATE USER 'app'@'10.0.%' IDENTIFIED BY '<由密鑰管理產生>';
GRANT SELECT, INSERT, UPDATE ON shop.orders TO 'app'@'10.0.%';

-- 連線強制加密：用戶端 ssl-mode=VERIFY_IDENTITY
-- 帳號層：CREATE USER ... REQUIRE SSL

敏感資料處理

手段適用情境
欄位層加密身分證字號、卡號等，即使 DBA 也不應看到明文
遮罩／去識別化測試與報表環境不使用真實個資
雜湊只需比對、不需還原的值（如密碼，見密碼儲存）
最少蒐集與保存不需要的資料不蒐集，到期即刪除
