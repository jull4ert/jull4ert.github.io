容器與編排加固

縮小映像、不用 root、限制能力，並以網路政策隔離。

原則

  • 使用精簡且受信任的基底映像，固定版本（最好用 digest），並定期重建與掃描。
  • 多階段建置，最終映像不含編譯工具與原始碼。
  • 以非 root 使用者執行；檔案系統唯讀；移除不必要的 Linux capabilities。
  • 密鑰不寫進映像或環境變數明文，改由密鑰管理注入（見 DevOps）。
  • 編排層：限制 Pod 權限、設定資源上限、以網路政策限縮橫向移動。

各技術實作

範例為最小示意，用來說明做法，套件 API 會隨版本調整，實作時請對照該版本的官方文件。上方篩選列可只顯示你用的技術。
# 多階段：最終映像只含執行所需
FROM <build-image>@sha256:<digest> AS build
...
FROM <minimal-runtime-image>@sha256:<digest>
RUN useradd --uid 10001 --no-create-home app
COPY --from=build /out /app
USER 10001
ENTRYPOINT ["/app/server"]

# 執行時
docker run --read-only --cap-drop ALL \
  --security-opt no-new-privileges  myapp:1.0
securityContext:
  runAsNonRoot: true
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true
  capabilities: { drop: ["ALL"] }
  seccompProfile: { type: RuntimeDefault }
resources:
  limits: { cpu: "500m", memory: "256Mi" }

另需：NetworkPolicy 預設拒絕、套用 Pod Security Standards 的 restricted 等級、限制 ServiceAccount 權限、不使用 latest 標籤。
