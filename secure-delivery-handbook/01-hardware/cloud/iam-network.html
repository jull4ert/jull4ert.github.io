雲端身分、儲存與日誌

雲端事故最常見的三件事：權限過大、儲存公開、沒有紀錄。

原則

  • 根帳號／全域管理員：啟用 MFA、不日常使用、不建立長期存取金鑰。
  • 人員用單一登入與角色，不用長期金鑰；服務用受管理身分／角色。
  • 權限最小化，定期用工具檢視過度授權。
  • 儲存貯體／Blob 預設禁止公開，確有需要才例外並審核。
  • 啟用組織層級的稽核日誌，保存到獨立且受保護的位置。

各技術實作

範例為最小示意，用來說明做法；指令與選項會隨版本、廠商調整，實作前請對照官方文件，並先在測試環境驗證。上方篩選列可只顯示你用的技術。
# 阻擋 S3 貯體公開
aws s3api put-public-access-block --bucket <bucket> \
  --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

# 啟用多區域 CloudTrail
aws cloudtrail create-trail --name org-trail --s3-bucket-name <log-bucket> --is-multi-region-trail
aws cloudtrail start-logging --name org-trail
# 儲存帳戶禁止匿名公開存取
az storage account update --name <account> --resource-group <rg> --allow-blob-public-access false

# 以角色指派授予最小權限（範例為唯讀）
az role assignment create --assignee <principal-id> --role "Reader" \
  --scope /subscriptions/<sub>/resourceGroups/<rg>

活動記錄（Activity Log）請設定診斷設定，匯出到 Log Analytics 或儲存體以長期保存。

# 儲存貯體啟用公開存取防護
gcloud storage buckets update gs://<bucket> --public-access-prevention

# 授予最小權限角色
gcloud projects add-iam-policy-binding <project> \
  --member="user:<email>" --role="roles/viewer"

Cloud Audit Logs 的管理活動日誌預設啟用；資料存取日誌需視需求另外開啟。
