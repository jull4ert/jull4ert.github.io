責任分界

我方、客戶、雲端或主機商各負責什麼。邊界不清楚，事故時就會變成互相推諉。

下表是常見的預設切分，只是起點。實際分界必須寫進合約（見 責任範圍）並在簽約前與客戶確認。

依層級的責任（以我方開發並維運為例）

層級我方客戶雲端／主機商
實體機房與硬體——負責
虛擬化與基礎網路——負責
作業系統與平台有維運合約時負責：修補、加固自管主機時負責託管服務時負責
網站與 API 程式碼負責：安全開發、掃描、修補驗收、提供需求—
第三方套件與外掛負責盤點與更新（合約範圍內）自行安裝的外掛自負—
資料與其分類依指示處理、保護負責：決定蒐集什麼、保存多久、取得當事人同意—
帳號與權限我方人員帳號、系統管理帳號客戶端人員帳號與其密碼管理雲端主帳號依持有人
網域、DNS、憑證依約代管者負責續約與設定自持有者負責續約—
備份與還原依合約範圍執行並演練確認需求（RPO／RTO）、驗證可用提供基礎設施功能
事故通報我方範圍內事故通知客戶對當事人與主管機關通報（控管者）通知其平台層事件

常見灰色地帶

  • 客戶自己改了主機設定或上傳了外掛，之後出問題算誰的？要在合約寫明「客戶自行變更不在保固範圍」。
  • 客戶提供的帳號密碼太弱或多人共用：我方要書面提醒並留下紀錄。
  • 雲端帳單與權限是客戶的帳號，我方只拿到委派權限時，責任以委派範圍為準。
  • 第三方服務（金流、簡訊、地圖）故障：我方負責整合，不保證其可用性。
