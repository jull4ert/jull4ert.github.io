解決方案設計

決定要做成什麼形狀：固定流程或自主 agent、檢索或工具、人在哪裡把關

問題定義清楚後，下一步是決定解法的形狀。這一區的核心觀念是：用最簡單、最可控的設計達成目標，只在必要時才增加自主性與複雜度。

設計原則多為業界通用的工程判斷；其中 workflow 與 agent 的區分引用 Anthropic 的文章。具體產品的功能請以官方文件為準，本區不比較特定產品。

建議順序

  1. 固定流程或自主 agent：怎麼選，常見模式
  2. 檢索、工具與微調：三種「讓模型知道更多、做更多」的方式
  3. 人機分工：人要在哪裡把關，怎麼設計核可
  4. .NET MVC＋Vue 的架構：分層、介面、模型的位置
  5. 自建、購買或設定：什麼時候不要自己做
  6. 為失敗而設計：模型出錯、服務中斷時系統怎麼辦
