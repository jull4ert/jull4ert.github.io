評估與品質

把「好不好用」變成數字：驗收標準、評測集、評分方式、上線後監控與回歸

沒有評估，你只有感覺；有了評估，你才能向客戶證明有效、知道改了之後是變好還是變壞、並在出問題時迅速定位。這一區是 FDE 與「做 demo 的人」差距最大的地方。

技術範例以 ASP.NET Core MVC（.NET 8）＋ Vue 3，前後端同一個 .NET 專案為基準，並以練習專案 sample/TicketDesk 為例。若你的專案是 .NET Framework 的 ASP.NET MVC 5，觀念相同，但建置與測試指令、專案檔格式不同。
本區的數字（TicketDesk 的 78%、88% 等）是練習專案在替身模型上實際跑出來的結果，用來說明方法；換成真實模型後必須重新評測。

建議順序

  1. 驗收標準：品質門檻與安全底線，事先寫好並簽認
  2. 建立評測集：來源、分層、標註、開發集與保留集
  3. 評分方式：精確比對、規則、模型評審與人工
  4. 回歸測試：每次修改都重跑，並追蹤歷史
  5. 上線後監控：看得見漂移、覆寫與成本
  6. 分析與處理失敗：錯誤分類、在對的層修正、記錄已知限制
