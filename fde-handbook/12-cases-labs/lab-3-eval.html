Lab 3：評測、錯誤分類與安全缺口

用評測集找出問題，在對的層修正，並避免過度配合

目標：分析開發集與保留集的失敗，補上保留集暴露的安全缺口，並理解為什麼不能直接把保留集的錯誤「修到過關」。

預估時間：90 分鐘　前置：Lab 0；讀過 06 評估與品質

步驟

  1. 執行 dotnet test --logger "console;verbosity=detailed"，記錄 dev 與 holdout 的輸出（正確率、失誤案例、未升級案例）。
  2. 用錯誤分類表，替每個失誤（d15 至 d18、h04、h07）標記原因與應修正的層。
  3. 你會發現保留集有一個安全缺口（h04：帳號被盜用卻沒升級）。設計並實作修正，讓它升級，並寫一個單元測試。
  4. 再想一個問題：來信 #8（發票寄錯、包裹也沒到）目前被放行。這算不算缺口？你要怎麼決定？寫下理由。
  5. 討論：h07（「收據」）能不能直接把「收據」加進 FakeLlmClient 的帳務關鍵字？這樣做的問題是什麼？你會怎麼做才算合理？
  6. 把你加的新案例（至少 6 筆，取自你對真實情境的想像）放進開發集，重新量測。

參考解答

1. 在規則層修正（確定、便宜、不依賴模型）

新增 Services/SecuritySignals.cs：

using System.Text.RegularExpressions;

namespace TicketDesk.Web.Services;

/// <summary>帳號被盜用、盜刷、詐騙等資安事件字眼：一律交給人，不管模型怎麼分類。</summary>
public static class SecuritySignals
{
    private static readonly Regex Pattern = new(@"盜用|被盜|盜刷|詐騙|駭客|外洩|釣魚", RegexOptions.Compiled);

    public static bool Looks(string? text) => !string.IsNullOrEmpty(text) && Pattern.IsMatch(text);
}

在 TriageService.TriageAsync 呼叫模型之前加入旗標，並在 Validate 中把它列入「需要人工」的條件：

if (SecuritySignals.Looks(ticket.Subject + " " + ticket.Body))
{
    flags.Add("security-sensitive");
}
// ...
var needsHuman =
    flags.Contains("possible-injection") ||
    flags.Contains("security-sensitive") ||     // 新增
    flags.Contains("invalid-category") ||
    confidence < MinConfidence || ...

2. 測試

// ---- Lab 3：資安事件字眼一律交給人 ----
public class SecurityEscalationTests
{
    private sealed class ConfidentLlm : ILlmClient
    {
        public Task<LlmTriage> TriageAsync(string subject, string maskedBody, CancellationToken ct = default) =>
            Task.FromResult(new LlmTriage("account", "normal", 0.95, "草稿", "理由"));
    }

    [Fact]
    public async Task Account_takeover_is_escalated_even_when_model_is_confident()
    {
        var svc = new TriageService(new ConfidentLlm(), new InMemoryAuditLog(), TimeProvider.System);
        var result = await svc.TriageAsync(new Ticket { Id = 1, Subject = "帳號異常", Body = "我的帳號被盜用，有人用我的帳號登入。" }, "t");
        Assert.True(result.NeedsHuman);
        Assert.Contains("security-sensitive", result.Flags);
    }

    [Fact]
    public async Task Ordinary_account_question_is_not_flagged_as_security()
    {
        var svc = new TriageService(new ConfidentLlm(), new InMemoryAuditLog(), TimeProvider.System);
        var result = await svc.TriageAsync(new Ticket { Id = 1, Subject = "忘記密碼", Body = "我登入不了帳號。" }, "t");
        Assert.DoesNotContain("security-sensitive", result.Flags);
        Assert.False(result.NeedsHuman);
    }
}

3. 關於 #8 與 h07

  • #8（多意圖）：是否算缺口取決於業務風險。若客戶認為「一封信混了兩件事就該由人看」，可以加規則（例如偵測到兩個以上類別的關鍵字就降低信心或轉人工）。這是需要和客服主管討論的決定，不是你自己決定。
  • h07：把「收據」直接加進關鍵字，等於「看著保留集改答案」，保留集就失去意義，分數也不再代表泛化能力。合理的做法是：把「收據」的案例加進開發集、改規則，然後另外取得新的保留集來檢查。
  • 也要記得：保留集只有 8 筆，88% 與 78% 的差異不具統計意義。
