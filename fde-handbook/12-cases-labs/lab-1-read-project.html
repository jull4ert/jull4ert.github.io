Lab 1：讀懂專案與資料流

不改程式，只靠閱讀回答七個問題

目標：建立對 TicketDesk 的心智模型，並練習用 Claude Code 當探索助手，同時自己驗證它的回答。

預估時間：60 分鐘　前置：Lab 0

步驟

  1. 先自己花 15 分鐘讀 Services/TriageService.cs，在紙上畫出「遮罩 → 呼叫 → 驗證 → 規則 → 稽核」。
  2. 回答下方七個問題，每題都要寫下你的依據（檔案與行）。
  3. 用 Claude Code 問同樣的七題，比較它的答案與你的答案；找出它說錯或含糊的地方（不要只相信它）。
  4. 畫出分層圖，標出哪些元件是「不可信的外部依賴」。

預期結果

  • Q1 個資遮罩發生在哪裡？在呼叫模型之前還是之後？
  • Q2 「需不需要人工」是模型決定的，還是程式決定的？決定的條件有哪些？
  • Q3 模型呼叫丟出例外時，使用者與稽核各會看到什麼？
  • Q4 稽核紀錄寫了什麼？故意不寫什麼？
  • Q5 哪些測試保護「遮罩」？哪些保護「安全底線」？
  • Q6 這個專案目前缺少哪三樣，是上線前一定要補的？
  • Q7 把 FakeLlmClient 換成真實模型，哪些檔案要改、哪些不用？為什麼？

檢核清單

  • 七題都有附檔案依據
  • 能不看程式畫出分層圖
  • 找出至少一個 Claude Code 答得不夠精確的地方

參考解答

請先自己做完再看。解答只是其中一種合理的做法。

參考答案
  • Q1：TriageService.TriageAsync 內，呼叫 llm.TriageAsync 之前，用 PiiMasker.Mask(ticket.Body)（注意：只遮罩內文，主旨沒有遮罩，這是一個值得討論的缺口）。
  • Q2：由程式決定。TriageService.Validate 中，因為疑似注入、無效類別、信心低於 0.7、類別為客訴或其他、優先為高而需要人工。
  • Q3：捕捉例外後回傳旗標 llm-error、NeedsHuman=true，並寫稽核；使用者看到的是需人工的結果而不是 500 錯誤。
  • Q4：寫時間、操作者、動作、單號、類別、優先、信心、是否需人工、旗標；不寫來信原文與個資。
  • Q5：PiiMaskerTests、Personal_data_is_masked_before_reaching_the_model、Audit_entry_is_written_without_raw_body；安全底線是 EvalTests 的 Assert.Empty(unescalated)。
  • Q6（其中三項）：身分與權限（操作者是固定字串）、稽核與資料持久化（目前在記憶體）、核可流程的後端強制。其他合理答案也可：姓名與地址遮罩、監控、成本上限。
  • Q7：只需新增或啟用 ILlmClient 的實作與註冊（Program.cs）；TriageService 與測試不用改，但評測集必須重新跑，不能沿用替身的數字。
