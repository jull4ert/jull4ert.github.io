Lab 0：環境與跑起專案

確認 .NET、測試與網站都能在你的機器上運作

目標：把 TicketDesk 跑起來，看懂它的畫面與測試輸出。

預估時間：30 分鐘　前置：已安裝 .NET 8（或更新的 SDK，且能執行 .NET 8 專案）；選用：Node.js

步驟

  1. 打開終端機，進入 sample/TicketDesk/。執行 dotnet --list-sdks 與 dotnet --list-runtimes，確認有 .NET 8 的執行階段。
  2. 執行 dotnet test TicketDesk.sln。如果你的 NuGet 設定含有需要驗證的私有來源而還原失敗，請確認專案根目錄的 nuget.config 是否生效（它只使用 nuget.org）。
  3. 執行 dotnet run --project src/TicketDesk.Web，用瀏覽器打開終端機顯示的網址。
  4. 依序點選來信 #1、#3、#5、#6、#8，各按一次「AI 分流」，記錄分類、優先、信心與是否「需人工」、旗標。
  5. 打開下方的稽核紀錄，確認每次分流都有一筆，內容不含來信原文。
  6. （選用）用 claude -n "FDE-Lab0" 啟動 Claude Code，請它「用三句話說明這個專案做什麼」，並自己對照 README.md 檢查它說得對不對。

預期結果

在手冊建立時，於作者的環境實際執行，結果為：

  • dotnet test：26 個測試全數通過（遮罩 5、分流規則 9、民國年 10、評測 2）。
  • 網站正常啟動，首頁載入 tickets-app.js。
  • #1：billing／normal／信心 0.95／不需人工。
  • #5：complaint／high／信心 0.95／需人工。
  • #6：billing／low／信心 0.99／需人工，旗標 possible-injection（來信內夾帶了指令）。
  • #8（發票寄錯、包裹也沒到）：shipping／normal／信心 0.9／不需人工（這是 Lab 3 要討論的一個隱憂）。

你的數字應該一致；若不同，先檢查是否改動了專案檔案。

檢核清單

  • 26 個測試通過
  • 能說出 #6 為什麼被標示為需人工
  • 稽核紀錄中沒有任何來信原文
  • 寫下一件讓你意外的觀察

參考解答

請先自己做完再看。解答只是其中一種合理的做法。

常見狀況
  • 還原失敗（401 或 NU1301）：確認 nuget.config 與你的全域設定。
  • 埠被占用：加上 --urls http://localhost:5099。
  • 看到的數字不同：確認沒有設定 TICKETDESK_LLM 環境變數（那會改用真實模型）。
