信任、資安與合規

AI 專案能不能上線，常常取決於資安與法務；這一區教你怎麼讓客戶放心

客戶的資安、法務與稽核部門，決定你的專案能不能上線。FDE 要能和他們用同一種語言對話：資料去哪裡、誰能看、被怎麼保護、出事怎麼辦。

這不是法律意見。法規會修正，適用的版本與解釋因情況而異；涉及個資、跨境傳輸與行業監理的問題，請交由客戶的法務與合規人員，或你公司的法務判斷。
技術範例以 ASP.NET Core MVC（.NET 8）＋ Vue 3，前後端同一個 .NET 專案為基準，並以練習專案 sample/TicketDesk 為例。若你的專案是 .NET Framework 的 ASP.NET MVC 5，觀念相同，但建置與測試指令、專案檔格式不同。

建議順序

  1. 資料最小化與個資遮罩：送出的資料越少越好
  2. 提示注入與過度代理：模型會被輸入誘導，所以要在系統層防禦
  3. 稽核紀錄：事後能重建「誰、何時、做了什麼」
  4. 回答資安問卷：誠實、具體、有證據
  5. 個資法與合規基本觀念：台灣情境的重點與限制
  6. 供應商與工具審查：模型服務、外掛與 MCP 的風險
